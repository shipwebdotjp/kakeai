# Agent Access ロードマップ

[Agent Access 仕様](./spec.md) の実装完了後の拡張候補を整理する。ここに書いたものは約束された仕様ではなく、優先順位と依存関係を共有するための計画である。実装するときは、この文書を更新したうえで [spec.md](./spec.md) と [todo.md](./todo.md) に詳細を落とす。

## 方針

- 正本は `ContentDocument` と SQLite のままとする。Agent Access は操作コアを呼ぶ薄い束縛であり、束縛ごとに業務ロジックを持たない。
- 可逆な操作だけをエージェントへ公開する。実体削除、外部サービスへの公開、Adapter 設定の変更、TTS 以外の課金生成は人に限る（[ADR 0074](../adr/0074-agent-direct-reversible-operations.md)、[ADR 0077](../adr/0077-agent-tts-on-configured-adapters.md)）。
- 互換性は「追加は自由、破壊は版を上げる」で扱う。エージェントは古いスキーマをキャッシュし得るため、契約の変更は `schemaDigest` とプロトコル版で検知できなければならない。
- スキルは `schema.get` を正とし、操作スキーマや Template 契約を複製しない。
- 個人利用のローカルアプリを前提に、運用負荷より再現性と巻き戻しやすさを優先する。

## 現状の制約

A9 完了時点で認識している制約である。R1〜R3 の項目は、これらを解消または緩和するための候補を含む。

| 制約 | 影響 | 対応候補 |
| --- | --- | --- |
| `schemaDigest` は操作カタログを含むが、各操作の入出力スキーマを含まない | 操作の入力追加・変更をエージェントが検知できない | R1-1 |
| ソケットの `AGENT_PROTOCOL_VERSION` は `1` のまま | 破壊的変更時に旧クライアントとの互換性を判定できない | R1-1 |
| `tts.create` などはタイムアウト後の自動再送で Job が重複し得る | 二重生成・課金・待機の無駄 | R1-2 |
| ソケットのフレームキューと書き込みバックプレッシャーに上限がない | 大量要求時にメモリが膨らむ | R1-3 |
| `asset.list` のタグ検索は SQLite の JSON をメモリで後フィルタする | 素材数が増えるとページ取得が遅くなる | R2-1 |
| `script.edit`/`validate` は毎回ライブラリ全体の Asset・Face Set・Character を読み込む | 大規模ライブラリで編集のたびにコストがかかる | R3-1 |
| `job.list` はレンダー Job のみ | TTS・取り込み Job の一覧や一括待機ができない | R2-6 |
| `asset.import` は同一ユーザーが読める任意のローカルパスを受け付ける | プロンプト注入時に意図しないファイルを複製し得る | R1-5 |
| スキルの配布はリポジトリからのコピー／symlink | 導入と更新が手作業で、版の対応関係が分からない | R3-3 |
| プレビュー・レンダー品質の視覚確認は未提供 | エージェントは構文・保存検証までしか自律確認できない | R3-5 |

## R1 契約の安定性と安全性

エージェントが長期にわたり安全に接続できるための基盤。制作機能の追加より先に片付ける。

### R1-1 操作契約のダイジェストとプロトコル版

- `schema.get` に各操作の入出力スキーマ（またはその正規化ダイジェスト）を含め、`operationDigest` として返す。`schemaDigest` は Template・警告・操作カタログ・操作契約をまとめたものにする。
- 互換な追加（任意フィールド、列挙値の追加）は版を上げず、破壊的変更（必須化、削除、意味変更）では `AGENT_PROTOCOL_VERSION` を上げる。
- サーバーは対応プロトコル版の範囲を `schema.get` で返し、未知の版は `AGENT_PROTOCOL_MISMATCH` のまま拒否する。旧版サポートの終了予定を仕様に記載する。
- 完了条件: 操作スキーマを変更すると `operationDigest` が変わり、破壊的変更では旧クライアントが安定したコードで拒否される。契約のドリフトを検出するテストがある。

### R1-2 すべての変更操作の冪等化

- `script.edit` と同じ `requestId`（または `idempotencyKey`）を `work.create`、`tts.create`、`tts.createBulk`、`composition.create`、`composition.publish`、`render.start`、`job.cancel` にも導入する。
- 要求ハッシュを保存し、同じ ID・同じ内容は保存済みの結果を返す。同じ ID・異なる内容は `IDEMPOTENCY_CONFLICT` とする。Job を返す操作は既存 Job を返し、新しい Job を作らない。
- `asset.import` は内容ハッシュによる既存の重複排除を維持しつつ、同じ要求の再送で同じ Asset を返す。
- 完了条件: タイムアウト後に同じ要求を再送しても、ScriptVersion・Job・Composition・Asset が増えない。再送と衝突をテストで区別する。

### R1-3 ソケットの流量制御・取消・ピア確認

- 接続ごとの未処理フレーム数、応答バッファ、同時実行数を上限付きにする。超過は安定コード（例: `AGENT_BACKPRESSURE`）で返し、接続を落とさない。
- 実行中操作のキャンセル要求を追加する。Job 投入済みの操作は Job キャンセルへ委ね、読み取りは打ち切る。タイムアウトは処理の中断を保証しない現状の注意を維持する。
- macOS の `getpeereuid` 等でソケット接続元が同一ユーザーであることを確認する。必要ならエージェント ID ごとの許可操作・レート制限を設定できるようにする。
- 完了条件: 過負荷時もメモリとレイテンシが有界で、同一ユーザー以外の接続が拒否される。キャンセルが Job 状態へ反映される。

### R1-4 エラーカタログと再試行可否

- `schema.get` に安定エラーコードのカタログ（意味、`retryable`、推奨される確認操作、`issues` の形）を追加する。
- エラーコードの追加・非推奨の規則を定め、既存コードの意味を変えない。束縛固有コード（MCP/CLI）と操作コアのコードを区別して返す。
- 完了条件: エージェントがコードだけで再試行・再読込・停止を判断でき、未知コードは安全側（再試行しない）に倒せる。

### R1-5 素材取り込みのガードレール

- 取り込み可能なルートの許可リスト、拒否パターン（認証情報・SSH 鍵・システム領域など）、symlink の解決方針を設定可能にする。
- 取り込み前にサイズとメディア種別を確認し、巨大ファイルのコピーを避ける。取り込み元パスは引き続きログ・正本・来歴へ残さない。
- 既定は現行の同一ユーザー信頼モデルを維持し、厳格化は任意設定とする。プロンプト注入対策として、エージェントが指定したパスを利用者へ確認する UI は将来の検討対象とする。
- 完了条件: 拒否対象のパスが安定コードで拒否され、許可領域だけが取り込まれる。パスが成果物へ漏れない。

## R2 制作フローの拡張

A9 の制作スキルを、より大きなライブラリと反復制作に対応させる。

### R2-1 素材検索のスケール

- タグを正規化した `AssetTag` リレーション（または同等の索引）へ移し、タグ AND / OR を DB 側で絞り込む。ファイル名は FTS または `LIKE` 用の索引を使う。
- `createdAt desc, id desc` の固定順と不透明 cursor は維持し、タグ絞り込み後も重複・欠落のないページングを保証する。総件数、ソート（新しい順・名前順・尺順）、尺・寸法・音声有無などのメタデータ絞り込みを追加する。
- 保存済み検索（名前付きフィルタ）は、制作スキルが同じ素材集合を再現するために有用なら追加する。
- 完了条件: 1万件規模の素材で、タグ複合検索とページングが全件スキャンなしに一定時間で返る。既存の HTTP・ソケット・MCP・CLI が同じ契約を使い続ける。

### R2-2 TTS 制作フローの強化

- TTS Job の冪等キーを `(scriptVersionId, narrationSegmentId, speechText, voiceProfileId/voiceId, speedScale)` のハッシュで持ち、同じ入力の再投入で Job を増やさない。
- 「最新台本の再読込 → Segment と読み上げテキストの照合 → Take 添付」を 1 操作にまとめる `tts.attach`（仮）を検討する。`baseScriptVersionId`、`jobId`、`expectedSpeechText` を受け、不一致なら `SCRIPT_BASE_STALE` または専用コードで拒否し、成功時は `script.edit` と同じく新しい ScriptVersion を作る。操作コアの `line.assignTake` を呼ぶ薄い操作とする。
- `tts.createBulk` の Job 群をまとめて待つ、進捗を返す、失敗分だけ再投入する導線を追加する。
- 読み取り専用の `voiceProfile.list` / `voiceProfile.get`、Adapter の稼働確認、声・モデル一覧を Agent Access に追加する。エージェントは設定を変更できない。
- 課金・外部送信を伴う Adapter について、利用者の明示許可（Adapter ごとの allowlist）と概算コスト表示を検討する。既定はローカル Adapter のみ。
- 完了条件: 同一セリフの再生成で Job が重複せず、テキスト変更後の誤添付が防げる。TTS の状態確認と再試行がスキル手順だけで完結する。

### R2-3 Character・Voice・Face Set の読み取り面

- `voiceProfile.list` / `voiceProfile.get`（読み取り専用）を追加し、locale・Adapter・声の対応をエージェントが確認できるようにする。
- `faceSet.list` / `faceSet.get` を追加し、`standing.set` の `expressionId` 選択を推測なしで行えるようにする。
- `character.addFromLibrary` に `key` を導入し、同一 `script.edit` 内で `line.setSpeaker` / `standing.set` から参照できるようにする。これによりコピーと割り当ての 2 回往復を減らす。
- 台本内 Character の名前・外見・声を編集する操作（`character.setName`、`character.addAppearance` など）を操作コアに追加する。ライブラリ自体の変更は引き続き非公開。
- 完了条件: ライブラリからコピーした Character を、追加の手作業なしにセリフ・立ち絵・表情へ割り当てられる。

### R2-4 作品・言語版・履歴の操作

- `languageEdition.create` / `languageEdition.clone` を追加し、多言語制作を Agent Access から開始できるようにする。翻訳候補は `script.save` または新しい `script.translate` で新しい版として保存する。
- `script.list`（Edition 内の版一覧）、`script.diff`（版間の構造差分）、`script.restore`（指定版の内容で新しい版を作る）を追加する。復元は既存 UI と同じく新しい ScriptVersion の追加であり、可逆。
- `work.list` に検索・状態フィルタ、`work.update`（タイトルなど可逆なメタデータ）を追加する。
- サムネイル（`thumbnail.*`）と字幕（`subtitle.export`）を読み取り／生成操作として追加する。PNG・SRT は派生データであり、正本を書き換えない。
- 完了条件: エージェントが言語版の追加、履歴比較、復元、サムネイル・字幕出力まで、UI と同等の制作判断を行える。

### R2-5 Job 操作の一般化

- `job.list` をレンダー以外の TTS・取り込みにも拡張し、`kind`・状態・作品・言語版で絞り込めるようにする。現在のレンダー履歴互換は維持する。
- queued の TTS・取り込み Job のキャンセル、Job の進捗購読（ポーリングの代替）、複数 Job の一括待機を追加する。
- 完了条件: 長尺操作の状態確認・キャンセル・再開判断が `job.*` だけで完結し、ポーリング回数が有界になる。

## R3 品質・運用・配布

### R3-1 参照スコープの読み込みとキャッシュ

- `script.edit` / `script.validate` で、操作と文書が参照する Asset・Face Set・Composition・Character だけを読み込む。ライブラリ全体の走査をやめる。
- Asset メタデータや Face Set の読み取りキャッシュを置く場合は、更新・取り込み・publish で確実に無効化する。単一プロセス・単一ライターの前提を崩さない。
- 完了条件: 大規模ライブラリでも編集・検証のレイテンシが参照数に比例し、キャッシュ不整合がない。

### R3-2 監査ログと帰属の可視化

- エージェント操作の監査ログ（agentId、操作名、requestId、対象作品・版、結果コード、所要時間）を保存する。読み上げテキストや素材パスなど機微な内容は記録しない。
- Web UI にエージェント操作の履歴・差分・帰属フィルタを追加し、巻き戻しの判断を支援する。
- 完了条件: 「誰が・いつ・何をしたか」を利用者が確認でき、失敗した操作も追跡できる。

### R3-3 スキルの配布と版管理

- `skills/kakeai-production` と `skills/kakeai-composition` をバージョン付きで配布し、利用中のアプリの `schemaDigest` / `operationDigest` と互換か確認できるようにする。
- インストール手段（同梱 CLI の `skills install`、npm パッケージ、runtime ごとの symlink）を用意し、更新時の差分とロールバックを可能にする。
- スキル本文の文言テストは書かず、参照する操作名・リンク・スキーマダイジェストの整合だけを検証する。
- 完了条件: 利用者が 1 コマンドでスキルを導入・更新でき、互換性のない組み合わせは導入前に検出される。

### R3-4 視覚確認（後続フェーズ）

- プレビュー画像・フレーム抽出・レイアウト検査・コントラスト検査を読み取り専用の操作として追加し、エージェントが保存前後に視覚的な破綻を確認できるようにする。
- 自動修正は行わず、検出結果と該当 Cue／Scene を返す。最終判断と承認は人に残す。
- 視覚確認の操作面は A9 の非ゴールであり、R3 でも独立したフェーズとして扱う。
- 完了条件: エージェントがテキスト溢出・重なり・コントラスト不足を保存前に検出できる。レンダー品質の最終承認は人のまま。

### R3-5 外部接続・クラウド（非ゴールの再検討）

- リモート MCP、HTTP 経由のエージェント接続、クラウドレンダーは、利用形態が変わった場合にのみ再検討する。ローカル単一ライターとファイル権限保護の前提を崩す場合は、新しい ADR で信頼境界を定義する。
- 完了条件: 導入する場合でも、認証・監査・テナント分離・課金の責任範囲が ADR と仕様で明示される。

## 優先順位

| 優先 | 項目 | 理由 |
| --- | --- | --- |
| 高 | R1-1 操作契約ダイジェスト／プロトコル版 | エージェントのキャッシュと互換性に直結する |
| 高 | R1-2 変更操作の冪等化 | タイムアウト再送での二重生成を防ぐ |
| 高 | R2-1 素材検索の索引化 | 制作スキルの検索品質と性能の前提 |
| 高 | R1-3 ソケット流量制御・ピア確認 | ローカル操作面の安定性と安全性 |
| 中 | R2-2 TTS 冪等化・`tts.attach` | 音声制作の反復コストを下げる |
| 中 | R2-3 Voice/Face Set 読み取り・`key` 対応 | 制作往復を減らす |
| 中 | R2-4 言語版・履歴・復元 | 多言語・反復制作の入口 |
| 中 | R3-1 参照スコープ読み込み | 大規模ライブラリでの性能 |
| 中 | R3-3 スキル配布・版管理 | 導入・更新の再現性 |
| 低 | R2-5 Job 一般化 | 運用が複雑になった段階で必要 |
| 低 | R3-2 監査ログ／UI | 複数エージェント運用時に必要 |
| 低 | R3-4 視覚確認 | 独立フェーズとして後続 |
| 低 | R3-5 外部接続 | 現行の非ゴールを維持 |

## 変わらない原則

- エージェントは実体削除、外部公開、Adapter 設定の変更、TTS 以外の課金生成を行えない。
- すべての台本変更は新しい ScriptVersion の追加であり、既存版を書き換えない。
- 操作の意味は束縛に依存しない。MCP・CLI・将来の束縛は同じ操作コアを呼ぶ。
- スキルは `schema.get` を正とし、契約を複製しない。
- 視覚品質の最終判断は人に残す。
