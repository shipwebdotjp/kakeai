# ライブ配信ロードマップ

[spec.md](./spec.md) を正とする。この文書は、v1の後に検討する拡張を、優先度と依存関係つきで整理する。ここに書いたものは約束された仕様ではなく、必要になった時点で個別に仕様化する。

## 方針

- まず「Kakeaiで作った台本とキャラクターで、30分のライブを止めずに配信する」を安定させる。
- 配信の操作、チャット投稿、モデレーションは人間の境界を維持する。アプリは読み取りと演出に集中する。
- ライブの進行は、コンポジションのタイムラインではなく、状態とキューで考える。
- 人間のピンを優先し、AIは残りを埋める。AIの自律性は、品質と安全の実績を見てから上げる。
- 見た目の再利用は、ライブパッケージの契約を壊さない範囲で増やす。

## 優先順位

| 優先 | 項目 | 何を解くか | 依存 | 着手のトリガー |
| --- | --- | --- | --- | --- |
| 高 | v1の安定（P1〜P6） | パッケージ書き出し、ステージ、プレイアウト、コメントコーナー、テストモード、実YouTube | なし | 今すぐ |
| 高 | 運用品質 | ステージ再接続、音声失敗、TTS/LLMタイムアウト、ログの読みやすさ | v1 | 最初の30分配信で問題が出たとき |
| 中 | OAuthの公開・検証 | 定期配信でリフレッシュトークンの7日失効を避ける | OAuth方針、Googleの検証 | 週次配信を続けるとき |
| 中 | 素材集（フィラー） | 時間が余ったときの話題・ネタ・退避素材の自動選択 | スパインとショープロファイル | 30分配信で尺の調整が頻発したとき |
| 中 | コメントコーナーの改善 | 鮮度、重複、投稿者多様性、Super Chat優先、コメント主への配慮 | v1のコメント選択 | コメントが増えて選別が大変になったとき |
| 中 | ローカルLLMの品質・速度 | 実YouTubeのコメント応答の体験 | v1 | 初回配信で遅い・弱いと感じたとき |
| 低 | 外部LLMの解禁 | 匿名要約だけを外部LLMへ送る | データ処理ADR | ローカルLLMで品質が足りないとき |
| 中 | ステージテンプレート | ニュースデスク以外のソロ、コメントフォーカス、素材フルスクリーン | ステージの状態契約 | 番組のバリエーションが増えたとき |
| 中 | VOD連携 | 配信ログから台本・字幕・チャプターを作る | ログ、Kakeaiの台本編集 | アーカイブを編集して出したくなったとき |
| 低 | 即時コメント割り込み | 台本の途中で、関連性の高いコメントを拾う | 話題一貫性のガード、コメント選択の実績 | コーナー方式に慣れ、即時性の需要が出たとき |
| 低 | AIの自律進行 | 人間ピンなしでもコメントコーナーを回す | v1のコメント品質、安全フィルタ | 人間の介入が少なくても破綻しない実績が出たとき |
| 低 | YouTube書き込み | AIの返答をチャットにも投稿する、配信を作成する | 新しいOAuthスコープ、モデレーション設計 | チャットにもテキストを出したいとき |
| 低 | 多言語ライブ | `en-US`などのロケールでライブを行う | 多言語の声、テーマのフォント | 英語版の需要が出たとき |
| 低 | 配信の自動復帰 | サーバ・ステージ・YouTube接続の自動復旧 | 運用品質 | 配信の長時間化・無人化が必要になったとき |

## 将来の候補

### 1. コメント体験

| 項目 | 内容 | 注意 |
| --- | --- | --- |
| Super Chat優先 | 金額・メンバー状態を読み、コメントコーナーの候補に加点する | 読み取りのみ。返金・決済は扱わない |
| 投稿者多様性 | 同じ投稿者の連続採用を抑える | スコアと別の枠制御が要る |
| コメントの要約 | 長いコメントを短く要約してカードに出す | 個人情報とニュアンスの扱い |
| コメント主への配慮 | 表示名を出すか、伏せるかを選ぶ | プライバシー設定 |
| 即時割り込み | 関連性が高いコメントだけ、文の切れ目で拾う | 話題の一貫性、進行の複雑さ（v1では非ゴール） |

### 2. 進行と構成

| 項目 | 内容 | 注意 |
| --- | --- | --- |
| 素材集（フィラー） | 時間が余ったときの話題・ネタ・退避素材を自動選択 | スパインとの優先順位 |
| ショープロファイル編集UI | スパイン、素材のScene参照、コメントポリシーをGUIで編集する | v1はJSON/エージェント/自動生成 |
| 書き出しUI | Kakeaiの画面からライブパッケージを書き出す | v1は`live_export` JobとCLI |
| セグメントの動的調整 | 残り時間に応じて、コメントコーナーの回数・尺を変える | 目標尺は目安のまま |
| オープニングの自動化 | カウントダウン、開始時刻、BGM | 自動開始は誤操作のリスク |
| エンディングの自動化 | お礼、次回予告、クリップ | VODとの連携 |
| AIの自律進行 | 人間ピンなしでコメントコーナーを回す | 品質と安全の実績が必要 |

### 3. ステージと見た目

| 項目 | 内容 | 注意 |
| --- | --- | --- |
| ステージテンプレート | ニュースデスク、ソロ、コメントフォーカス、素材フルスクリーン | 状態契約を増やしすぎない |
| ステージ編集UI | スロットの位置・大きさ・背景を編集する | v1は固定レイアウト |
| 素材カードの拡張 | 動画、グラフのアニメーション、BGM付きカード | 実行時のコンパイルを避ける |
| キャラクターの演技 | 頷き、ジェスチャー、視線、考え中のモーション | 顔レイヤーと状態機械の拡張 |
| 縦型・複数解像度 | 9:16や別解像度のステージ | テーマと素材カードの再レイアウト |

### 4. 配信と運用

| 項目 | 内容 | 注意 |
| --- | --- | --- |
| YouTube書き込み | チャット投稿、配信作成、タイトル・サムネイル設定 | 新しいOAuthスコープ、誤投稿の防止 |
| OAuth公開・検証 | 定期配信でリフレッシュトークンの7日失効を避ける | Googleの検証、プライバシーポリシー、Testingからの移行 |
| Super Chatの扱い | 読み取り、優先、表示 | 決済・返金は扱わない |
| 配信の自動復帰 | サーバ・ステージ・YouTube接続の自動復旧 | 二重配信・二重音声の防止 |
| リモートステージ | 別マシンのブラウザでステージを表示する | 認証、ネットワーク、遅延 |
| クラウド実行 | クラウド上でライブを実行する | ローカル前提の撤廃、コスト、セキュリティ |
| 複数利用者 | チームでコンソールを共有する | 認証、権限、同時操作 |

### 5. VODと再利用

| 項目 | 内容 | 注意 |
| --- | --- | --- |
| 配信ログから台本 | 実際に話した内容をScriptVersionの候補にする | 人の承認が必要 |
| 配信ログから字幕 | 音声と字幕のタイミングをSRTにする | TTS音声の尺と実際の再生尺 |
| 配信ログからチャプター | セグメントと話題からチャプターを生成する | YouTubeのチャプター規則 |
| クリップ生成 | コメントコーナーや名場面を切り出す | 権利とプライバシー |

### 6. TTSと音声

| 項目 | 内容 | 注意 |
| --- | --- | --- |
| ストリーミングTTS | 文の先頭から音声を流し、初動を早くする | アダプタ契約の拡張 |
| BGM・効果音 | コーナーの切り替え、オープニング、エンディング | 音声のダッキング、権利 |
| 声の切り替え | コメントの内容に応じて話者を変える | キャラクターの一貫性 |
| 感情制御 | 表情と声のトーンを連動する | アダプタごとの差 |

### 7. LLM

| 項目 | 内容 | 注意 |
| --- | --- | --- |
| ローカルLLMの品質・速度 | モデル選択、量子化、GPU/CPU配分、P95レイテンシ | 実YouTubeはローカル固定 |
| 外部LLMの解禁 | 匿名要約だけを外部LLMへ送る | 同意・保持期間・削除を含む新しいADRが必要 |
| 応答品質の評価 | コメント応答の長さ、正確性、ペルソナ、繰り返し | 人手評価とログ |

## v1でやらないこと

- YouTubeの配信作成・開始・終了、チャット投稿、モデレーション。
- コンポジションのタイムラインをライブの進行に使うこと。
- 人間の承認遅延を入れること。
- 台本の途中への即時コメント割り込み。
- AIだけでの完全自律進行。
- 実YouTubeのコメントを外部LLMへ送ること（v1はローカルLLMのみ）。
- 多言語ライブ、縦型ステージ、クラウド配信。
- VODの自動編集。
