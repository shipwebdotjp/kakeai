# 台本の編集意味論は共有操作コアに置き、UI・API・MCPは同じ操作を呼ぶ

Status: accepted

台本の編集は、シーン分割・行削除・Cue 範囲変更のような副作用（ID 採番、参照の付け替え、効果トリガーの剪定、既定値の補完）を伴う。これらを Web UI のフォームモデルだけに置くと、HTTP API や AI エージェントは「全体が届いた後の参照整合」しか共有できず、同じ意味論を束縛ごとに再実装することになる。そこで、`ContentDocument` を入力に取り、新しい文書と作成 ID・警告を返す純粋な操作コアを `packages/script-edits` に置き、Web UI・API・Agent Access（MCP / CLI）は同じ操作を呼ぶ。操作の契約は `packages/contracts` に置き、操作コアは永続化・トランスポート・認証を持たない。

## Considered Options

- UI の編集ロジックをそのまま残し、API とエージェント向けに別実装を追加する。→ 意味論が二重化し、UI で扱えない文書やエージェントだけ壊れる操作が生まれるため不採用。
- 汎用の JSON Patch を受け、適用後に正規化する。→ 中間状態が不正になり得て、操作名・エラー・作成 ID を安定して返せないため不採用。
- サーバー側だけに操作コアを置き、UI は全量保存を続ける。→ UI とエージェントで結果が一致せず、「API では正しいが編集画面で扱えない」状態を検証できないため不採用。

## Consequences

- `apps/web` の `form.ts` は入力アダプタと表示へ縮小し、文書変更は操作コアへ移す。移行は構造操作から始め、フィールド編集を最後にする（[../editor-core/todo.md](../editor-core/todo.md)）。
- タイミング解決は `@kakeai/video/timeline` を UI と API で共有する。編集画面はプレビュー応答の解決結果に依存せず、編集中の文書から分割点を求める。
- 保存は引き続き `ContentDocument` 全体の置換とし、操作コアは保存しない。操作結果が保存検証を通ることを不変条件にする。
- Agent Access は操作コアの上に載る束縛となり、`script.save`（全体置換）に加えて操作の一括適用を公開する。操作の一括適用と原子性、基準版の不一致は束縛が扱う（[../agent-access/spec.md](../agent-access/spec.md)）。
- 操作が純粋関数になるため、将来のアンドゥ・リドゥや差分適用の土台になる。
