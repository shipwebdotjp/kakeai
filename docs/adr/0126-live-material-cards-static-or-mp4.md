# ライブの素材カードは静止PNG/HTMLまたは短い無音MP4に限定する

Status: amends ADR-0120

ライブの中央スロットに表示する素材カードは、v1では**静止PNG/HTMLまたは短い無音MP4**に限定する。コンポジションHTMLのGSAPタイムラインをライブで再生するためのiframeランナーやフルPlayerは使わない。

## Context

- 現行のコンポジションHTMLは、`gsap.timeline({ paused: true })`を作成し、`window.__timelines`へ登録する。プレイヤーがタイムラインを進めない限り、Sceneの時間制御や短いアニメーションは再生されない。
- [ADR-0120](./0120-live-runtime-separate-from-composition.md) は、ライブでHyperFrames Playerを使わない一方、素材カードをコンポジションHTMLのiframeとして書き出す決定を含んでいた。カード内アニメーションを許可すると、プレイヤーなしでは動かないという矛盾がある。
- ニュースの見出し・画像・引用カードは、静止画でも十分に成立する。動きが必要なカードは限られる。
- ライブの中央カードは、書き出し後の見た目が固定され、実行時にコンパイルされない方が安定する。Asset URLの文字列置換は、パスやエスケープの事故を招く。

## 決定

- v1の素材カードは、静止PNGまたは静的なHTML、もしくは3〜5秒程度の短い無音MP4とする。
- ステージの中央スロットは、静止カードを`img`、動画カードを`video`、静的HTMLをスクリプトなしのsandbox iframeで表示する。コンポジションHTMLのiframeランナー、ミニランナー、フルPlayerは使わない。
- カードは音声を持たない。manifestに`hasAudio: false`を記録し、起動時に検証する。
- カードのAsset URLは、HTML文字列の置換ではなく、書き出し時のAsset Resolverでパッケージ相対URLとして生成する。
- カードはKakeaiの単一Sceneから、既存のコンパイラとラスタライザで書き出す。nested Compositionと動画ゲートはv1では拒否する。
- iframe内のミニランナーやフルPlayerが必要になった場合は、別のADRで再生・停止・seekの契約を定める。

## Considered Options

- 静止PNG/HTMLだけにする。→ 動きのあるカードを作れないが、v1のニュースカードには十分で、最も安定するため、これを基本とする。
- 短い無音MP4を許可する。→ 動きのあるカードを作れるが、書き出しコストとファイルサイズが増えるため、特殊カードに限定する。
- iframe内に小さなGSAPランナーを置く。→ カード内のタイムライン制御は可能になるが、新しい再生契約とセキュリティ境界が必要になるため、v1では不採用。
- HyperFrames Playerを埋め込む。→ ライブの状態駆動と競合し、プレイヤーの再生位置と音声キューが二重管理になるため不採用。

## Consequences

- 素材カードの表示が安定し、実行時のコンパイルやプレイヤー依存がなくなる。
- カード内の複雑なアニメーションはできない。必要な場合はMP4に書き出すか、将来のミニランナーを待つ。
- カードの見た目は書き出し時に固定される。ニュース内容の変更はパッケージの再書き出しになる。
- 無音検証とAsset Resolverにより、カードの音声混入とURL破損を防げる。
- ADR-0120の「素材カードをコンポジションiframeとして埋め込む」部分は、この決定で置き換える。
