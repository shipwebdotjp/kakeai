# 欠損Assetの復旧はcontent-addressedパスへの上書きに単純化する

Assetの `storageKey` は内容ハッシュ由来であるため、同一SHA-256の再アップロードで実体が欠損・破損している場合は、同じパスへ検証済みの一時ファイルを上書きして取り込み直す。旧ファイルの隔離や公開パスからの一時除外、`storageRestored` の区別は持たない。個人利用ではこの経路の競合が稀で、原子的置換の厳密さが見合わないため。

## Consequences

同一バイト列の重複排除（既存行の再利用）は維持する。上書き中に読み出しが走る可能性は残るが、取り込みJobで `processing` に戻すためUIはreadyとして扱わない。
