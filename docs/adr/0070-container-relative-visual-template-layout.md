# Visual Template のレイアウトをコンテナ相対にし、Cue 本体をコンテナにする

Visual Template のレイアウト寸法を、1920×1080 固定pxではなく**親要素のサイズに追従するコンテナ相対**で書けるようにする。テンプレートは与えられた箱を埋め、`container-type: size` を自分で設けた要素の `cqw` / `cqh` から無単位のスケール変数を導いて、文字・余白・角丸・アイコン径をすべてその倍数で表す。固定pxを書かない。縦方向の差は内蔵flexで吸収する。

あわせて、コンパイラは Cue 本体（`.kakeai-cuebody`）を `container-type: size` にする。これにより任意の Cue が意味のある `cq` 単位を使える。従来は `scene.device-frame@1` の画面要素だけがコンテナで、全面に置いた Cue の `cq` はビューポート基準という暗黙依存になっていた。内側により近いコンテナ（device-frame の画面など）がある場合は、既存どおりそれが優先される。

最初の適用先は `chat.thread@1` とする。スマートフォン枠（9:16）・ノートPC枠（16:9）・全面（`none`）で同じ入力・同じレイアウトコードを使い、幅の違いだけを吸収する。

## Considered Options

- **基準サイズで描いて contain/cover で縮尺する**（既存の Composition slot と同じ `tan(atan2())` イディオム）。→ リフローせず、縦横比が変わると余白または見切れになる。「同じ内容が幅違いで同じように見える」要求に合わないため不採用。
- **幅ごとに別テンプレートを用意する**（phone 版・desktop 版）。→ 重複そのもので、保守が二重になるため不採用。
- **Canvas Profile を任意寸法に拡張する**。→ 最終出力は 1920×1080 固定であり、Canvas Profile は入れ子 Composition 自身の内部キャンバス専用（[ADR-0066](0066-canvas-profile-as-version-property.md)）。テンプレートのリフローとは別の関心事なので不採用。
- **`chat.thread@1` を `scene.device-frame@1` の画面に入れ子にする**。→ エディタは入れ子テンプレートを編集できず（非破壊保持のみ）、メッセージを編集できないため不採用。任意テンプレートの入れ子編集は別途。

## Consequences

- 新規テンプレートは固定pxを書かない規約を取る。既存テンプレートは据え置き、順次移行は必須としない。
- `.kakeai-cuebody` が `container-type: size`（`contain: size layout style`、paint は含まない）になる。Cue 本体は `inset: 0` でサイズが親依存のため影響せず、既存テンプレートは `cq` を使っていない。入れ子 Composition の `cqw` は、内側のコンテナが無い場合に Cue 本体を基準にするようになり、暗黙のビューポート依存が解消される。
- `chat.thread@1` は `frame: phone | laptop | none` を持ち、`phone` では静的ステータスバー（時刻・ダイナミックアイランド・Wi‑Fi・バッテリー）を描く。実時刻は読まず、シーク決定性を保つ。
- プレビューとレンダーで `cq` が一致するには、Player がキャンバスを 1920×1080 のレイアウトサイズで描き、表示は transform で拡縮することが前提となる。ビューポート基準でレイアウトする実装に戻すと一致しなくなる。
- `messages` というデータ駆動の Template Field を追加する。アイコンは既存の `media` / `nestedMedia`（単一キー前提）では表せないため、このフィールドが自前でアイコン用の素材ピッカーを持つ。
