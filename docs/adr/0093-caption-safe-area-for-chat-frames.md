# 字幕セーフエリアを設け、チャットのスマートフォン・デスクトップ枠をその上に収める

`chat.thread@1` の `phone`・`desktop` は、キャンバス下端に字幕の高さぶんの領域（字幕セーフエリア）を予約し、パネルをその上に収める。セーフエリアはテーマの `textRoles.caption`（`fontSize`・`lineHeight`）と `surfaces.caption`（上下padding・border）から導出し、既定テーマでは216px（下端72px + 2行 + 上下padding）とする。`phone` には加えて、空の入力欄と送信アイコンだけの静的な「入力ドック」を置き、メッセージ列の下端をドックの上に固定する。

## Context

焼き込み字幕は固定層で、キャンバス下端から72pxに置く。一方、チャットのスマートフォン枠は高さ94%のパネルを中央寄せしていたため、下端が字幕の表示帯に入り、最新メッセージが字幕に重なっていた。

`card` / `overlay` のレイヤー順では解決しない。`card` では字幕がチャットを覆い、`overlay` ではチャットが字幕を覆うため、どちらかを選ぶと必ず読めない側が出る。重なりを避けるには、両者の描画領域を物理的に分ける必要がある。

## Considered Options

- **レイヤー順や字幕の不透明度で逃げる。** → `card` と `overlay` のどちらでも破綻し、字幕かメッセージのどちらかが読めなくなるため不採用。
- **入力ドックだけを足してメッセージ列を上げる。** → メッセージと入力欄の衝突は解けるが、パネル自体が字幕帯に残るため、字幕が入力ドックに重なる。二段構えが必要だった。
- **字幕が出るCueのときだけ予約する。** → シーンごとに端末の大きさが変わり、同じ作品内で見た目が揺れる。コンパイルも字幕区間の有無に依存して複雑になるため不採用。
- **字幕の位置・行数・下端余白を固定値で持つ。** → テーマ編集で字幕サイズを変えると重なりが再発するため不採用。テーマトークンから導出し、CSS変数 `--kakeai-caption-safe` で渡す。
- **セーフエリアを `laptop`・`none` にも適用する。** → `laptop` はキーボードベースを含めた寸法の再フィットが別途必要で、`none` は全画面表示の意味を決める必要がある。今回は `phone`・`desktop` に限定し、残りは [../chat-template/roadmap.md](../chat-template/roadmap.md) に回す。
- **`composer` のような入力フィールドを追加する。** → 入力内容も送信先も持たない装飾であり、正本JSONとエディタを複雑にするだけなので不採用。スマートフォン枠の標準外観とする。

## Consequences

- 既定テーマの1080pで、スマートフォンパネルは約457×812px（従来は約571×1015px）になり、本文は約17px相当に小さくなる。入力欄付きのスマートフォンとしての説得力は上がるが、6件の長文は窮屈になるため、プレビューでの確認を前提とする。
- デスクトップ枠は幅制約のためパネルサイズは変わらず、位置だけが字幕の上へ上がる。
- 字幕は2行までを保証する。3行以上は既存の `text_overflow` 警告の対象であり、重なりを保証しない。
- セーフエリアはテーマの字幕スタイルに追従する。字幕を大きくするテーマでは端末がさらに小さくなる。
- 見た目の変更であり入力契約は変えないため、[ADR-0071](0071-pre-release-appearance-changes-without-version-bump.md) に従い `@2` は切らない。
