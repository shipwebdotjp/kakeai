# 可変Sceneテンプレート `explanation-scenes@1` を導入し、固定5シーン版を読み取り専用で残す

シーン構成を可変にする `explanation-scenes@1` を導入し、新規作成・保存はこれを使う。
構成は「導入 → 要点0件以上 → 結び」の順で、新規作品は要点3件で開始する。
`contentDocumentSchema` は `template.id` で構成規則を切り替える判別unionとし、
旧 `explanation-5-scenes@1`（導入→要点×3→結び）も引き続き検証・読み出し・描画できるようにする。

理由は二つある。一つ目は、ContentDocumentの `schemaVersion` を据え置いたまま表現を増やすためには、
保存済みの版を書き換えずに新テンプレートを追加する必要があること。二つ目は、旧テンプレートで保存された
既存作品（MVP開発中に作成済み）を壊さずに読み・編集・プレビュー・レンダーできる状態を保つため。
`schemaVersion: 1` は変えない。`explanation-5-scenes@1` は新規作成に使わない。

## Considered Options

- `schemaVersion` を上げて旧版を新テンプレートへ移行する。→ 保存済みデータの書き換えと移行コードが必要になり、MVPの「移行コードを先回りして持たない」方針に反するため不採用。
- 旧テンプレートを削除する。→ 既存作品が読めなくなるため不採用（ADR-0009/0018の版不変性に従い、参照が消えるまで残す）。

## Consequences

- 編集UIは要点Sceneの追加・削除・並べ替え、背景とカード（各1件・Scene全体）の選択・解除を提供する。Scene IDは保存・移動で維持し、追加時だけ新規発行する。
- 編集UIが扱えない複数VisualCue、`lines`／`offset` 範囲、他のVisualTemplateは保存時に削除・変更せず保持する。
- コンパイラはシーン配列を汎用的に反復し、両テンプレートを同一処理系で描画する。同一Scene内の重ね順は `media.full-bleed@1` を最背面、`media.card@1` をその上に固定する。
- `explanation-5-scenes@1` の描画・検証コードは、どの保存済み版からも参照されなくなった時点で削除してよい。
