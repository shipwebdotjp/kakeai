# エージェントによる素材のお気に入り・アーカイブの切り替え

Status: accepted

## 背景

素材の整理は `Asset.favoritedAt` と `Asset.archivedAt` の2つの印で行う。HTTP の `PATCH /assets/:assetId`（`updateAssetRequestSchema`）と Web UI はタグ・お気に入り・アーカイブを更新できるが、エージェントに公開されているのは `asset.tag` だけで、お気に入りとアーカイブは人間専用だった。

エージェントは素材を取り込んで使い終わったあとに、候補を絞り込み、不要な素材を既定の検索から隠したい。しかし `favorited` / `archived` を切り替える手段が無いため、素材ライブラリにはエージェントが取り込んだ素材がそのまま溜まり、制作のたびに同じ候補を人が整理する必要があった。

お気に入りとアーカイブはどちらも真偽値の印で、`false` を返せば元に戻る。実体ファイル・行・台本参照は消えず、レンダーも壊れない。したがって [ADR 0074](./0074-agent-direct-reversible-operations.md) の可逆操作として公開できる。実体削除（`asset.delete`）は引き続き人専用とする。

## 決定

`asset.update`（mutation）を追加し、素材のお気に入りとアーカイブを切り替えられるようにする。`AGENT_PROTOCOL_VERSION` は `1` のまま据え置く（加算的変更）。

- 入力は `{ assetId, favorited?, archived? }` で、少なくとも1つを必須とする。出力は `{ asset }`。既存の `updateAsset` をそのまま呼び、印の付け方（現在時刻の設定と null への解除）を複製しない。
- `tags` は含めない。タグは既存の `asset.tag` が担い、`asset.update` は整理の印だけを扱う。`asset.update` にタグを足すのは将来も非破壊でできるため、意味の重複を今作らない。
- アーカイブは行を残し、既定の `asset.list` とピッカーから隠すだけである。台本の参照、Job の入力スナップショット、レンダーは影響を受けない。この性質を仕様に明記する。
- `requestId` は持たず、冪等台帳に載せない。状態（true / false）は同じ入力の再送で変わらないが、`favoritedAt` / `archivedAt` は再設定のたびに現在時刻へ更新される。既存 HTTP の挙動を変えないため、この時刻の更新は許容する。タイムアウト後は `asset.get` で状態を確認してから再実行する。
- `asset.delete` は公開しない。`asset.tag` は従来どおり残す（削除は破壊的変更になるため行わない）。
- アーカイブ済みの素材も `asset.update` で解除でき、`asset.list` の `archived: "only"` で見つけられる。

## Considered Options

- `asset.tag` を `asset.update` に統合し、タグ・お気に入り・アーカイブを1操作にする。→ カタログは短くなるが、既存の `asset.tag` の削除は破壊的変更になり、プロトコル版の引き上げとスキル移行が必要になる。加算的な `asset.update` を選ぶ。
- `favorited: true` を「未設定のときだけ設定する」set-once にする。→ 再送の結果が時刻まで完全に同じになるが、HTTP の既存挙動を変える。印は検索と表示にだけ使われ、時刻の更新に実害が無いため、現行の挙動を維持する。
- `asset.favorite` / `asset.archive` の2操作に分ける。→ 操作数が増えるだけで、同じ素材の整理を1往復で済ませる利点が無くなる。1操作にする。
- 削除も公開する。→ 台本・Job・ライブラリの参照を壊し得る不可逆操作である。人専用を維持する。

## Consequences

- Agent Access 仕様の MCP 操作表・可逆操作の一覧・操作詳細・タイムアウト、roadmap、todo、制作スキル、ユーザーガイドを更新する。`operationDigest` と `schemaDigest` は変わり、束縛（MCP / CLI）とアプリは同じビルドで揃える。
- エージェントは取り込んだ素材を、制作中の候補としてお気に入りへ、不要になったものをアーカイブへ寄せられる。素材ライブラリの整理を人が最初からやり直す必要が減る。
- アーカイブは既定の検索から隠すだけなので、アーカイブ済みの素材を参照する既存の台本はそのままレンダーできる。
- この決定は恒久ではない。素材の一括整理、削除、タグを含む統合更新が必要になった場合は、取り消し手段と合わせて新しい ADR で判断する。
