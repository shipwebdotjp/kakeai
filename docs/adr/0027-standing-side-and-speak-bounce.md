# 立ち絵の左右配置と発話中バウンド

`character.standing@2` を追加し、入力を `{ characterId, appearanceId, side: "left"|"right", scale }` とする。`side` は離散値で、位置は左 `x=0.27` / 右 `x=0.73`、いずれも `y=0.86` に写像する。自由な `x`/`y` は持たない。

`@1`（自由な `x`/`y`/`scale`）は意味も描画も不変のまま残し、検証・描画を続ける。編集UIは保存時に `@2` を書き出す。`@1` の既存ScriptVersionは `@1` のまま描画され、見た目は変わらない。

理由は、左右を制作意図としてデータに残し、1シーン最大2体を明快に扱うため。自由座標のままだと「左右」がデータに残らず、UIの2枠制約と対応しない。テンプレート版の意味を不変に保つ方針（[ADR-0009](./0009-template-version-immutability.md)）に従い、同じ版を書き換えず新バージョンを追加する。

発話中のバウンドは `@2` の立ち絵に限る。立ち絵の `characterId` に話者（Speaker）が対応し、その話者が話すセリフ区間だけ `y` をゆっくり上下させる（GSAPのyoyo）。振幅・周期は描画側の規約とし、正本JSONには保存しない。話者が紐づかないセリフ、話していない立ち絵は静止する。`@1` はバウンドさせない。

## Considered Options

- `@1` の `x`/`y` を維持し、UIの左/右ボタンで座標を設定する。→ 「左右」がデータに残らず、既存 `@1` の描画にもバウンドが波及するため不採用。
- 1シーンに3体以上を許容する。→ 今回は最大2体・左右1体ずつに限定する。`side` の重複はUIで防ぐ。

## Consequences

- 編集UIは1シーンに左右1体ずつ最大2体を編集する。`side` の重複と3体目はUIで不可とする。
- ContentDocument は複数の立ち絵VisualCueと任意の `side` を従来どおり検証・保持する。UI範囲外のCue（`lines`/`offset`範囲、3体目など）は非破壊で保持する。
- コンパイラは話者→キャラクターの対応からScene内の発話区間を求めてバウンドを生成する。プレビューとレンダーで同一のタイムラインを使う。
- 当面の非対象: シーン内での立ち絵切替、表情の自動切替、口パク、任意座標。
