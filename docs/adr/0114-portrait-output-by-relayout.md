# 縦型出力はレターボックスやクロップではなくレイアウトの再構成で作る

Status: accepted

## Context

縦型（1080×1920）を既存の 16:9 レイアウトから作る方法は、大きく3つある。

1. 16:9 の描画結果を縮小して上下または左右に余白を付ける（レターボックス／ピラーボックス）
2. 16:9 を縦型の枠いっぱいまで拡大して切り抜く（クロップ）
3. 縦型のキャンバスに合わせてレイアウトを組み直す（再レイアウト）

Kakeai の動画は、字幕・テロップ・図表・立ち絵・挿入 Composition を含む解説動画で、画面の大部分が文字情報である。レターボックスは画面の 3 分の 1 以上が黒帯になり、クロップは左右の文字と図表が失われる。どちらも「読める解説動画」という前提を満たさない。

一方、既存のテンプレートは 1920×1080 を前提にした固定 px（本文の最大幅 1600px、カードの余白 90×160px、チャートのプロット幅など）で組まれており、キャンバスを差し替えるだけでは破綻する。

## 決定

- 縦型出力は、**縦型キャンバス用にレイアウトを再構成して生成する**。レターボックスとクロップを既定の生成方法にしない。
- コンパイラはキャンバス（`width` / `height`）を入力として受け取り、固定定数（`OUTPUT_WIDTH` / `OUTPUT_HEIGHT`）を既定値に格下げする。
- レイアウトはキャンバスから導出するメトリクス（コンテンツ幅、余白、タイプスケール、セーフエリア）で組み、テンプレートは縦型で縦積み・単一カラムへ組み替える。
- 16:9 の画像・動画素材は、全画面背景では cover（既存の `focalPoint` を中心に使う）、カード内では contain を既定とする。クロップで情報が失われることを前提に、素材の見え方はプレビューで確認できるようにする。
- 縦型で内容が収まらない場合（チャートの項目数、表の列数、長い見出しなど）は、黙って切らずに検証警告として返す。既存の「字幕が 2 行を超える」警告と同じ扱いにする。
- Composition Version は自身の `canvasProfile` を保つ。Work の出力形式と一致する Composition は全画面（full-bleed）に使え、一致しない Composition はシーン内の枠に収める。縦型 Work で全画面に置けるのは縦型 Composition だけとする。

## Considered Options

- 16:9 を縮小して黒帯を付ける。→ 実装は最小だが、縦型画面の大部分が余白になり、スマートフォンでの可読性がむしろ下がるため不採用。
- 16:9 をクロップする。→ 左右の文字・図表が失われ、解説動画として成立しないため不採用。
- 縦型専用のテンプレート一式を別に持つ。→ 見た目の自由度は高いが、テーマ・スキン・テンプレートの二重管理になり、片方だけ更新される事故が起きるため不採用。キャンバスをパラメータ化し、同じテンプレートで両方を組む。
- 縦型のときだけ全 px を一律に縮尺する。→ 16:9 の構図がそのまま中央に縮小されるだけで、再レイアウトにならないため不採用。

## Consequences

- `packages/video` のテンプレートは固定 px をキャンバス由来のメトリクスへ置き換える必要があり、テンプレートごとに縦型の組み方を定義する作業が発生する。
- 字幕・セーフエリア・タイプスケールの数値は縦型専用の値を持つ。16:9 の既存出力は数値変更の影響を受けないよう、横型のメトリクスは現行値を維持する。
- ビジュアルテーマはキャンバス非依存のまま（色・フォント・文字ロール）とし、縦型用のテーマを別に作らない。縦型の見え方はレイアウト側で吸収する。
- レンダー結果の寸法が Work ごとに変わるため、ゴールデンフレーム比較と、キャンバス外へのはみ出し検出をテストに追加する。
