# キャラクターライブラリは台本へコピーし、台本内の実体と schemaVersion を維持する

作品をまたいで使うキャラクターをアプリ共通の「キャラクターライブラリ」で管理する。
ライブラリのキャラクターを台本へ追加するときは、新しいローカルIDで**コピー**する。
台本内のキャラクター実体は従来どおり `ContentDocument` が保持し、`schemaVersion` は `2` のまま据え置く。
外観は任意の表示名 `label` を持ち、`schemaVersion` を上げずに追加する。

理由は、キャラクター実体を台本から外してグローバル参照にすると、`ContentDocument` の版上げ、
グローバル参照の検証、レンダースナップショットへのキャラクター凍結、既存版の移行が必要になり、
変更が大きいこと。台本の自己完結性（派生作品・多言語化で版を参照して対応付ける下地）も失われる。
コピー方式なら、ライブラリは再利用のためのテンプレートに留まり、台本は従来どおり自己完結する。

ライブラリ側の変更（名前・外観・声）は既存台本のコピーへ波及しない。作品ごとに調整したい場合は
その作品のコピーを編集するか、外観を分けてライブラリに登録する。

## Considered Options

- 台本はキャラクターをグローバルIDで参照する（`ContentDocument` v3）。→ 名称変更が全作品に波及する利点はあるが、版上げ・移行・スナップショット凍結・検証の全面改修が必要で、台本の自己完結性も失うため不採用。
- 作品ごとにキャラクターを手動作成する（現状維持）。→ 同じキャラクターを作品ごとに作り直す手間があり、声の対応付けも作品ごとにばらつくため不採用。
- 外観をライブラリのみで編集し、台本コピーでは編集しない。→ 外観のバリエーションは `label`（例「夏服」「冬服」）でライブラリに複数登録し、作品独自の外観は別エントリまたは作品コピーで対応する。

## Consequences

- `ContentDocument` は `schemaVersion: 2` のまま。`CharacterAppearance.label` は任意フィールドとして追加し、既存データを壊さない。
- キャラクターライブラリは Prisma のグローバルテーブルとして持つ。台本はライブラリを参照しない（コピーするだけ）ため、ライブラリ削除の参照ガードは不要。声プロファイルはライブラリのキャラクターから参照される間は削除を拒否する。
- 台本の `Speaker` はデータ上維持し、キャラクター選択に応じて1対1で自動生成・解決する。キャラクターを持たない既存の話者（ナレーター）とその参照は非破壊で保持する。
- per-work のキャラクター管理ページは廃止し、ライブラリ画面と台本編集のキャラクターセクションに統合する。
