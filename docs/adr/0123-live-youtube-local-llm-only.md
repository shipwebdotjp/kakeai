# 実YouTubeのコメント処理はローカルLLMに限定する

Status: amends ADR-0121

v1の実YouTubeでは、ライブチャットのコメント分析と応答生成に**ローカルLLMだけ**を使う。コメント本文、安全要約、生成結果を外部LLMへ送らない。fixtureテストでは外部LLMを使ってよいが、渡すのは合成コメントだけに限る。

## Context

- [ADR-0121](./0121-youtube-read-only-comment-source.md) はYouTube連携を読み取り専用にした。しかし、読み取ったコメントをLLMへ渡し、ログに保存し、要約・スコア・生成文を作ることは、APIの書き込みとは別のデータ処理になる。
- YouTube APIのデータポリシーは、プライバシーポリシーと同意、保存データの削除手段、不要になったAPIデータの期限付き削除を求める。コメント由来のスコアや要約を「派生データ」として扱う必要があるかは、外部LLMへ送る場合に特に確認が必要になる。
- 外部LLMへコメントを送ると、送信範囲、保存期間、削除、同意、委託先の扱いが増える。v1の最初の配信では、ここを未決のまま有効化しない方が安全である。
- ライブはローカルMac上で動く。ローカルLLM（OpenAI互換のループバックエンド、例: Ollama）なら、コメントをマシンの外へ出さずに分析・応答生成ができる。
- fixtureコメントは実在の視聴者のデータではない。品質比較やプロンプト調整のために外部LLMを使っても、YouTubeの実データを外部へ送ることにはならない。
- ローカルLLMは、外部の大規模モデルに比べて品質・速度・文脈長で劣る可能性がある。コメント応答が間に合わない場合に台本を止めないためのバッファと退避キューが、より重要になる。

## 決定

- 実YouTubeの実行では、コメント分析役とライブディレクターにローカルLLMだけを使う。`llm.mode`は`local`を強制し、コメント本文・安全要約・生成結果を外部エンドポイントへ送らない。
- fixtureテストでは、`llm.mode`を`local`または`external`にできる。外部LLMに渡すのはfixtureコメントだけとし、実YouTubeのコメントを外部LLMへ送る経路を作らない。
- LLMの接続設定（`mode`・`baseUrl`・`model`・任意のAPIキー）は、ライブアプリのローカル設定に置く。ライブパッケージには接続設定を入れない。
- 生コメントは既定で実行中のメモリだけに保持し、長期保存しない。ログに残す場合は、実行単位の短い保持期間（例: 24時間）と`live purge`コマンドを用意し、生コメントではなく投稿ID・匿名化した要約・スコアを残す。
- 分析役のスコア・要約・生成結果もYouTube API由来のデータとして扱い、保持期間と削除手段を持つ。
- OAuthを取り消したときは、トークンとコメント関連のキャッシュを削除する。
- ユーザーガイドに、保存するデータ、保持期間、削除方法、実YouTubeでは外部LLMを使わないことを記載する。
- 将来、実YouTubeで外部LLMを使う場合は、同意・保持期間・削除・匿名化・送信範囲・告知を含む新しいADRで判断する。

## Considered Options

- 外部LLMに匿名化した安全要約だけを送る。→ 実データの送信・保存・削除・同意の契約がまだないため、v1の初回では不採用。将来の候補にはなる。
- 実YouTubeは準備台本だけにし、コメント応答はfixtureテストだけにする。→ データリスクは最小だが、実コメントへの応答というライブの価値を初回に確認できないため、ローカルLLMで代替する。
- ずっとローカルLLMだけにする。→ 品質・速度の制約を固定してしまうため、v1の初回限定とする。将来の外部LLMは別ADRで判断する。
- YouTubeのHTTP APIをモックしてテストする。→ 実データの処理境界を検証できないため不採用。コメントソースとLLMの境界で差し替える。
- 生コメントを長期ログに保存してプロンプト改善に使う。→ 削除・保持期間・同意の負担が大きいため、既定では保存しない。必要なら短い保持期間とpurgeを付ける。

## Consequences

- 実YouTubeのコメントはマシンの外へ出ない。プライバシーと説明の負担が下がる。
- ローカルLLMの品質・速度・必要ハードウェアが、コメント応答の体験を左右する。モデル選択、量子化、タイムアウト、退避キュー、無音を置かないバッファ設計が重要になる。
- 外部LLMを使ったfixtureテストと、ローカルLLMを使った実YouTubeテストで、品質と速度を分けて評価できる。
- 実YouTubeの受け入れ条件は、ローカルLLMで30分の配信を止めないことになる。外部LLMの品質を前提にしない。
- 生コメントの長期保存をしないため、配信後の詳細な会話レビューは限られる。必要な場合は、同意と保持期間を決めた別の運用にする。
- 将来、外部LLMを実YouTubeで使うときは、データ処理の契約とユーザーへの告知を先に作る必要がある。
