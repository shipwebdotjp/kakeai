# text_overflow は文字幅で推定し、locale で基準を切り替えない

`text_overflow` 警告の行数推定は、文字数ではなく文字幅で行う。全角（CJK・全角形・絵文字）を2、ASCII・半角カナなどを1、結合文字・制御文字を0として数え、`charsPerLine` を全角換算の1行の幅と定義する。`locale`（`ja-JP` / `en-US`）によって基準を切り替えない。

背景は、英語版で実際には1〜2行に収まる字幕・本文に警告が出る誤検知である。従来の推定は全文字を全角1文字として数えていたため、英語（1文字あたり約0.47em）で約2倍厳しく見積もられていた。実測（テーマのフォントスタック、42pxのCanvas計測）では英文0.466em/文字・和文約1.0em/文字であり、半角1単位=0.5emと置く推定は約7%保守的で、単語折り返しの余白もほぼ吸収する。

## Considered Options

- locale別の倍率（`en-US` だけ `charsPerLine` を×1.8など）。→ 実装は最小だが、倍率が場当たり的で和英混在文に弱く、日本語文書内の英語も誤警告のままになるため不採用。
- 保存時に headless Chrome で実際の行数を実測する。→ 最も正確だが、保存のたびに約0.7〜1秒の遅延と直列キューが生じ、保存経路がブラウザ依存になり失敗時フォールバックも要る。[ADR-0014](./0014-text-overflow-warning-not-rejection.md) が厳密計量のコストを理由に警告方式を選んだ判断と不整合のため不採用。

## Consequences

- 和文のみの台本の判定は従来と一致する（和文はすべて2単位のため数学的に同一）。
- 英語は実効で約2倍の文字数が同じ行数に収まる（例: 字幕は半角76文字/行、本文は半角56文字/行）。和英混在文も幅で自然に推定できる。
- 分割できない長いトークン（URLなど）は幅の行数換算で数えるため、従来どおり警告対象になる。
- テーマの `fontSize` 上書きやプロポーショナルのばらつき・単語折り返しの厳密な再現はしない。警告は目安であり、最終判断はプレビューに残る（[ADR-0014](./0014-text-overflow-warning-not-rejection.md)）。
