# pre-1.0のローカルアプリではv1 APIを一括更新する

Status: accepted

Kakeai は pre-1.0 の個人用ローカルアプリで、v1 API の利用者は同梱の Web UI・CLI・MCP に限られる。互換用の経路を残すと、新旧の契約が同時に存在して実装と文書の正が分裂する。機能変更で API 契約を変えるときは、v1 の経路をその場で置き換える。

## 決定

- API のパス・DTO・必須パラメータを変更するときは、旧パスを互換用に残さない。呼び出し側（`apps/web`・`apps/cli`・`apps/mcp`・`apps/api` のテスト）を同じ変更で更新する。
- 破壊的変更は、必要に応じて DB 更新で旧データを破棄してよい。データ移行関数や旧形式の読み取り互換は、要件で明示された場合だけ設ける。
- API 契約書（`docs/mvp/api-contract.md`）は現行の契約だけを記載し、旧バージョンの経路を併記しない。変更の履歴は ADR とサムネイル等の仕様文書に残す。
- アプリ外のクライアント向けの安定版 API を提供する時点で、この方針を見直す新しい ADR を追加する。

## Considered Options

- v1 に互換用の旧エンドポイントを残す。→ ローカルアプリの同梱クライアントしか使わず、二重の契約を維持するコストだけが残るため不採用。
- v2 を追加して v1 を残す。→ バージョンを分けるほどの外部利用者がおらず、DB も一括更新できるため不採用。
- 旧データを移行する。→ 旧外観の Font Face は新しい locale 別契約に意味を保って変換できず、移行の正しさを説明できないため不採用。

## Consequences

- サムネイル外観APIは `/language-editions/:editionId/thumbnail-appearance` から `/works/:workId/thumbnail-appearance?languageEditionId=...` へ置き換わり、旧経路は 404 になる。
- アップデート時に旧サムネイル候補・外観値・旧形式のプリセットは失われる。Work・Edition・ScriptVersion・Asset は残る。
- 契約変更のたびに Web UI・CLI・MCP・テスト・文書を同じ変更で更新する必要がある。
