# 素材の正規化は必要時のみ遅延実行する

アップロード原本は原則そのままプレビューとレンダーに使い、`asset_ingest` は形式・長さ・寸法を検査してメタデータを記録する。原本を直接レンダーに使えない場合（非対応コーデック、可変フレームレート、回転メタデータなど）に限り、その必要時に `AssetRendition` を作る。理由は、全素材を一律にH.264/AAC・CFRやWAVへトランスコードするコストが個人利用に見合わないため。

## Considered Options

- 取り込み時に全素材を正規化する。→ 変換時間と失敗要因が増え、原本をそのまま使える場合に無駄なため不採用。

## Consequences

`AssetRendition` は必須ではなくなる。レンダー・プレビューのAsset解決は「Renditionがあればそれ、無ければ原本」を返す。受け入れ条件は「全形式を必ず正規化する」から「使えない入力だけ必要時に正規化する」へ変わる。
