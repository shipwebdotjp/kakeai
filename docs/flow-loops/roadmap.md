# 循環フロー ロードマップ

[spec.md](./spec.md) を正とする。この機能は既存の小さなグラフJSONを保ったまま、表示規則と許容する辺の種類を拡張する。任意グラフの自動レイアウトへは進まない。

## 導入順序

| フェーズ | 対象 | 依存 | 目的 |
| --- | --- | --- | --- |
| C1 | 契約・共通分類 | なし | `layout`、自己ループ、辺種別の導出を一意にする |
| C2 | レンダラー・警告 | C1 | 線形と循環で決定的な経路を描く |
| C3 | 編集UI | C1 | 利用者が意図を損なわず編集・並び替えできるようにする |
| C4 | 検証・文書 | C2–C3 | 保存、プレビュー、MP4の一致を確認し、出荷文書を同期する |

## 段階導入

### C1: 契約を先に固定する

`flow.diagram@1` の任意 `style.layout`、循環レイアウトのノード数制約、自己ループの本数制約を契約化する。辺種別は正本の列挙値にせず、既存の `from` / `to` とレイアウトから導出する。

成果は、既存Cueを変えずに新しい図を保存でき、レンダラーとUIが同じ意味で「後ろ向き」「自己ループ」「周回辺」を判断できることである。

### C2: 描画規則を実装する

線形の後ろ向き辺と自己ループを主経路から分離して描き、循環のノード位置・周回辺・補助辺・自己ループを決定的に描く。線形と循環の境界、横型と縦型、ノード数の境界を代表入力で確認する。

成果は、描画の見た目が入力順・キャンバス・シーク位置で揺れず、プレビューとMP4で一致することである。

### C3: 意図を編集できるUIにする

レイアウト選択、自己ループを許す辺フォーム、循環順を示すノード並び替えを追加する。既存Cueを編集しても、選択していない `layout` や `orientation` を不用意に書き換えない。

成果は、利用者が「循環」「再試行」「差戻し」を個別の隠し設定なしに編集できることである。

### C4: 仕上げと出荷判断

契約・レンダラー・フォームの振る舞いテストと、横型・縦型の視覚確認を行う。実装完了時点で既存のフローテンプレート仕様、台本契約、ユーザーガイドを実際の挙動へ同期する。

## 将来候補

| 候補 | 保留理由 |
| --- | --- |
| 辺ラベルや経路の衝突警告 | まず実例で、どの衝突が利用者の編集で解消不能かを確かめる |
| 3本以上の自己ループを持つ工程 | 小さな動画図ではラベルと矢印が読めなくなるため、専用の別表現が必要 |
| 反時計回りや開始位置の指定 | ノード並び替えと循環順だけで足りない実例が確認できてから検討する |
| 自動交差最小化・自由座標 | 正本と派生レイアウトの境界、プレビューとMP4の決定性を複雑にする |
| 辺のセリフ同期効果・周回アニメーション | Cue効果の対象・シーク安全性を広げるため、別機能として検討する |
