# 循環フロー仕様

## 目的と境界

この文書は `flow.diagram@1` に、反復工程と循環全体を過不足なく表すための `cycle` レイアウト、自己ループ、後ろ向きの辺を加える変更の正とする。既存の基本契約は [../flow-template/spec.md](../flow-template/spec.md)、台本の正本JSONは [../mvp/content-schema.md](../mvp/content-schema.md)、決定は [ADR-0118](../adr/0118-cyclic-flow-layout-and-loop-edges.md) を参照する。本書と既存フローテンプレート仕様が矛盾するときは、本書を優先する。

- 対象は、最大8ノード・16辺の小さなフロー図である。工程が戻る差戻し、同一工程での再試行、PDCAのような閉じた循環を区別して読めることを目標にする。
- 正本は引き続き `nodes` 配列と、ノードindexを参照する `edges` 配列である。ノード座標、SVG path、辺種別を正本に持たない。
- `flow.diagram@1` は維持する。今回の追加は任意入力の受理範囲を広げるもので、`layout` 未指定の既存Cueは従来どおり線形に描画する。
- 辺は従来どおり常時表示する。循環を示すためだけの自動回転、辺の登場アニメーション、任意keyframeは追加しない。ノードへのセリフ同期効果は従来のままとする。

## 用語と辺の意味

| 名称 | 判定 | 意味 |
| --- | --- | --- |
| 順方向辺 | 線形レイアウトで `to > from` | 配列順に沿って次の工程へ進む辺 |
| 後ろ向き辺 | 線形レイアウトで `to < from` | 差戻し、フィードバック、前工程への戻りを示す辺 |
| 自己ループ | `from === to` | 同一工程での再試行、継続、再確認を示す辺 |
| 周回辺 | 循環レイアウトで `to === (from + 1) % nodeCount` | ノード配列の周回順に沿う主経路の辺。最後のノードから最初のノードへの辺を含む |
| 補助辺 | 循環レイアウトで自己ループでも周回辺でもない辺 | 飛び越し、逆向きのフィードバックなどを示す辺 |

辺種別は `from`、`to`、レイアウト、ノード数から導出する。入力に `kind` や経路座標は追加しない。したがって、辺の意味を変えずに線形と循環の見せ方を切り替えられる。

## 入力契約

`style` に任意の `layout` を追加する。

```jsonc
{
  "title": "品質改善サイクル",
  "diagram": {
    "nodes": [
      { "label": "Plan" },
      { "label": "Do" },
      { "label": "Check" },
      { "label": "Act" }
    ],
    "edges": [
      { "from": 0, "to": 1 },
      { "from": 1, "to": 2 },
      { "from": 2, "to": 2, "label": "再確認" },
      { "from": 2, "to": 3 },
      { "from": 3, "to": 0, "label": "改善を反映" },
      { "from": 3, "to": 1, "label": "差戻し" }
    ]
  },
  "style": {
    "layout": "cycle", // linear | cycle。省略時 linear
    "orientation": "horizontal", // linear だけで使う。cycle では保存したまま描画に使わない
    "preset": "clean"
  }
}
```

- `style.layout` は `linear | cycle`。省略時は `linear` と解釈する。
- `linear` では `style.orientation` の `horizontal | vertical` を従来どおり使う。`cycle` では `orientation` を無視するが、線形へ戻したときの選択を失わないため保存値は保持する。
- `cycle` は3〜8ノードでのみ保存できる。2工程の往復は線形レイアウトと相互の辺で表す。ノード数1の反復は線形レイアウトの自己ループで表す。
- `edges[].from` / `to` は常にノード範囲内とする。`from === to` を許可する。
- 同じノードを始点・終点にする自己ループは最大1本とする。複数の再試行理由を表したい場合は1本の自己ループのラベルへまとめる。
- 既存どおり、辺は最大16本、ラベルは任意かつ最大32文字とする。ノードのラベル・caption、効果target、行triggerの検証規則は変えない。
- `cycle` は辺を暗黙に生成しない。周回を表す各辺は明示的に `edges` へ入れる。

## レンダリング

### 線形レイアウト

- ノードは従来どおり配列順に横または縦へ等間隔で並べる。
- 隣接ノード間の辺は直線で結ぶ。
- 非隣接の順方向辺は、主軸の順方向側の外側を通るベジェ曲線にする。後ろ向き辺は反対側の外側を通す。横型では順方向を下、後ろ向きを上、縦型では順方向を右、後ろ向きを左とする。
- 自己ループはノードの主軸と反対側に小さな閉じたベジェ曲線で置く。横型では上、縦型では左へ逃がし、矢印はノードへ戻る向きに付ける。

### 循環レイアウト

- ノード0をプロット上端の中心に置き、残りをノード配列順に時計回りで楕円周上へ等間隔に配置する。プロットはタイトル・字幕セーフエリアを避け、横型・縦型それぞれのコンテンツ領域に収める。
- 周回辺は、楕円の内周に沿って時計回りへ結ぶ。最後から最初への辺も同じ規則で描き、閉じた主経路として扱う。
- 補助辺は内周より内側のベジェ曲線で描く。複数の補助辺が同じ側へ集中するときは `edges` 配列順に一定のレーン間隔を付ける。交差を最小化する自動レイアウトは行わない。
- 自己ループは各ノードから楕円の外側へ張り出す。複数ノードの自己ループがあっても、各ノードの放射方向に置くため主経路と重ならない。
- 辺ラベルは経路中点付近の読みやすい側に置き、背景色の縁取りを維持する。狭い領域でラベル同士が衝突する場合も、経路や文字を暗黙に省略しない。編集者はプレビューで確認し、ラベル短縮または辺の整理を行う。

### 決定性と効果

- 配置・経路・補助辺レーンは、`layout`、ノード配列順、辺配列順、キャンバスプロファイルだけから決定する。同じ入力・同じシーク位置でプレビューとMP4は一致しなければならない。
- ノードの並び替えは既存どおり辺のindex参照と効果targetを追従させる。`cycle` では並び替えが時計回りの周回順も変更する。
- `appear` / `emphasize` / `spotlight` / `onset` はノードだけを対象にする。辺を強調・出現・周回アニメーションさせない。

## 編集UI

- フローフィールドに **レイアウト** として「線形」「循環」を追加する。循環を選ぶと向きの選択は非表示にし、保存済みの向きは削除しない。
- 辺の編集では同じノードを「から」「へ」に選べる。対象ノードに自己ループが既にある場合、その組合せを追加できないようにする。
- 循環レイアウトを選ぶと、ノードの並び順が「時計回りの順番」であることを表示する。↑／↓の並び替え、辺・効果参照の追従は既存の挙動を維持する。
- 線形で後ろ向きの辺、循環で補助辺または自己ループを追加したときは、プレビューで経路を確認するよう案内する。自動的な辺削除・並べ替え・経路編集は提供しない。

## 非ゴール

- ノードの自由配置、辺の手動経路編集、SVGやHTMLを正本として保存すること。
- 任意グラフの交差最小化、階層・段組み・力学モデルによる自動レイアウト。
- 自己ループを複数本持たせること、辺の太さ・形・矢印形状・色を個別指定すること。
- 辺を対象にしたセリフ同期効果、循環を示す常時回転アニメーション。

## 受け入れ条件

1. 既存の `flow.diagram@1` 入力で `layout` を省略すると、現在の線形表示と同じになる。
2. 線形の横型・縦型で、順方向辺・後ろ向き辺・自己ループを同時に保存、プレビュー、MP4レンダーできる。
3. 3〜8ノードの循環レイアウトで、`0 → 1 → … → last → 0` の周回辺、補助辺、自己ループを区別して描画できる。
4. 範囲外ノード、循環レイアウトでの2ノード以下、同一ノードの2本目の自己ループ、範囲外の効果targetは保存時に拒否する。
5. ノード並び替え後も、辺と効果targetは同じ論理ノードを指し、循環レイアウトでは新しい配列順で決定的に再配置される。
6. 同じ入力・同じシーク位置のプレビューとMP4で、ノード配置、辺の経路、効果状態が一致する。
