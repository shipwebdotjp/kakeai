# 素材タグ仕様

## 目的と境界

この文書は、再利用可能な素材ライブラリで素材を分類し、見つけやすくするためのタグの正とする。素材の取り込み・原本の不変性は [../mvp/spec.md](../mvp/spec.md)、HTTP契約は [../mvp/api-contract.md](../mvp/api-contract.md) を正とする。

- タグはユーザーが後から追加・削除できる表示用メタデータとし、素材の原本（`sha256`・`storageKey`・`kind`・寸法・長さ）とは独立に扱う。取り込み後の不変原則の例外は[ADR 0039](../adr/0039-asset-tags-mutable-metadata.md) に従う。
- タグは素材ライブラリ画面と素材ピッカーで付与・絞り込みできる。
- タグに階層・色・並び順は持たせない（フラットな文字列の集合）。

## データモデル

Assetはタグの配列を持つ。

```json
{
  "id": "ast_image_001",
  "tags": ["背景", "夏"]
}
```

- 保存は `Asset.tagsJson`（JSON文字列）。空配列は `NULL` として保存する。
- 読み書きは `packages/contracts` のZodスキーマで検証する。先頭・末尾の空白は除去し、空文字は除去し、重複は1つにまとめる。
- 1素材あたり最大30個、1タグ最大40文字。
- タグは作品に属さない素材属性であり、どの作品からも同じ素材のタグを共有する。

## 更新API

`PATCH /assets/:assetId` に `{ "tags": [...] }` を送り、タグ配列を丸ごと置き換える。存在しない素材は404 `RESOURCE_NOT_FOUND`、契約違反は422 `VALIDATION_ERROR` とする。

## 絞り込み

タグの絞り込みはサーバー側の検索クエリで行う。HTTPの `GET /assets`（Agent Access の `asset.list` も同じ契約）は、タグを `tags` で指定し、`tagMode` で `and`（指定したタグすべてを持つ素材）か `or`（いずれか1つを持つ素材）かを選ぶ。`tagMode` の既定は `and`。絞り込みはファイル名や種類などの他の条件と組み合わせられ、アーカイブ済み素材は既定で除外される（`archived` で `include` / `only` を選べる）。

- タグは `Asset.tagsJson` のJSON配列の要素として照合する。タグは引用符で囲まれた要素として保存されるため、`bgm` は `bgm_loop` に一致しない。
- 照合が SQLite の `LIKE` を通るため、ASCII の英字は大文字小文字を区別せず（`Summer` は `summer` に一致する）、非ASCII（日本語など）は区別する。
- `LIKE` のワイルドカード `_`（任意1文字）と `%`（任意文字列）はタグ文字列のままワイルドカードとして解釈される。これらの文字を含むタグでの検索は他のタグにも一致し得る（タグ `%` はタグを持つ素材すべてに一致する）。

検索は `sort`（`createdAt_desc` が既定、`createdAt_asc`、`filename_asc`、`duration_asc`）で並べ替えられ、1ページは `limit`（既定50、最大100）件。応答には絞り込み条件に一致する総数 `total` が含まれ、同じ条件のページングでは変わらない。

素材ライブラリ画面では、取得した一覧に対して同じタグ条件で表示を絞り込む。検索の正はサーバ側のクエリで、画面の絞り込みは表示上の補助である。

## 非ゴール

- タグの階層化・色分け・並び順の保持。
- タグのリレーション化と索引化（検索の走査コストは個人ライブラリの規模では支配的でない。将来課題とする）。
- タグの集計（件数の集計など）。
- 素材以外（作品・キャラクターなど）へのタグ付け。
