# テンプレート・レイアウト改善 仕様

## 目的と境界

この文書は、既存の VisualTemplate に対して可読性と画面内の構図を改善する、次の変更の正とする。台本の正本 JSON 契約は [../mvp/content-schema.md](../mvp/content-schema.md)、VisualCue の層と描画順は [../composite-visuals/spec.md](../composite-visuals/spec.md) を正とする。

- `flow.diagram@1`: ノードラベルをノード幅に応じて自動縮小し、読めない長さを警告する。
- `table.simple@1` / `chart.bar@1`: 幅プリセットを持たせ、同じ文字サイズのまま表示領域を狭められるようにする。
- `scene.device-frame@1`: デバイス全体の倍率と横方向の配置を指定可能にする。
- `list.callout@1`: 変更しない。既存の `width`（`long | medium | short`）と `align`（`left | center | right`）を使う。

これは全テンプレートへ共通 `scale` を追加する仕様ではない。文字の収まり、コンポーネントの占有幅、デバイスの見た目の倍率は別問題であり、単一の数値へ統合しない。

正式リリース前の見た目・既定値の更新として、対象テンプレートは `@1` を更新する。既存の保存済み入力が新しいレンダラーで異なる見た目になることは許容する（[ADR-0071](../adr/0071-pre-release-appearance-changes-without-version-bump.md)）。

## `flow.diagram@1`: ノードラベルの可読性

### レンダリング

- ノードラベルは、ノードの内側の利用可能幅と文字幅見積りから、基準サイズ以下へ自動縮小する。ラベルの見た目を大きくするための入力フィールドは追加しない。
- 基準サイズは現行の30px、最小サイズは18pxとする。テーマの型組み倍率は従来どおり適用する。
- 基準サイズで収まるラベルは、現行と同じサイズで描く。縮小は必要なラベルだけに行う。
- 最小サイズで一行に収まらない場合は、テキストを黙って切り捨てない。通常の折返しを許可し、警告で編集者に知らせる。短い日本語ラベルがノード幅の都合だけで「データ収 / 集」のように不自然に折れるケースは、自動縮小で回避する。
- `caption` と辺ラベルのサイズ・折返し規則は今回変更しない。

### 警告

`computeContentWarnings` は出力形式とノード数・向きからノード幅を見積もり、次を返す。

| code | path | 条件 |
| --- | --- | --- |
| `flow_label_reduced` | `diagram.nodes[i].label` | 基準サイズより小さくして描画する必要がある |
| `flow_label_overflow` | `diagram.nodes[i].label` | 最小サイズでも一行に収まらず、折返し表示になる |

- 警告は保存を拒否しない。編集者はプレビューで読みやすさを確認し、必要ならラベルを短くする。
- 文字幅の見積りは既存の全角換算ユーティリティを使い、レンダラーと警告で同じ制約値を共有する。横型・縦型で異なるノード幅になることを考慮する。

## `table.simple@1` / `chart.bar@1`: 幅プリセット

### データ

両テンプレートの `style` に任意の `width` を追加する。

```jsonc
{
  "style": {
    "width": "medium" // wide | medium | narrow。省略時は wide
  }
}
```

- `width` は `wide | medium | narrow` の列挙値で、未指定時は `wide` と解釈する。
- `wide` は各テンプレートの現在の最大幅を維持する。
- `medium` は `wide` の75%、`narrow` は60%を上限とする。出力形式のコンテンツ幅より広げない制約は従来どおり維持する。
- 表とグラフで `wide` の絶対px値が異なることは許容する。プリセットは同じ絶対幅ではなく、各テンプレートでの相対的な占有幅を意味する。
- この変更は文字・罫線・棒・軸を `transform: scale()` で縮小しない。表では外枠の最大幅、棒グラフではフレームとプロットの最大幅を変える。
- 狭い幅によりセルやカテゴリ名が折り返されることはある。既存の表セル・行列数、グラフのカテゴリ・系列数に対する警告は維持する。幅指定そのものを保存エラーや新しい警告にはしない。

### 編集UI

- `table.simple` と `chart.bar` のテンプレート定義は、`style.width` を **幅** として `wide` / `medium` / `narrow` の選択肢で公開する。
- フォームでは未指定を `wide` と表示するが、既存入力を編集せず保存するときに不要な値を追加しない。利用者が明示的に変更したときだけ保存する。

## `scene.device-frame@1`: 倍率と配置

### データ

`scene.device-frame@1` の入力に任意の `scale` と `placement` を追加する。

```jsonc
{
  "screen": { "kind": "media", "assetId": "asset-screen", "fit": "cover" },
  "frame": "laptop",
  "scale": 0.8,
  "placement": "left" // left | center | right。省略時は center
}
```

- `scale` は有限数の `0.6..1`。省略時は `1` と解釈する。
- `placement` は `left | center | right`。省略時は `center` と解釈する。
- 倍率は、画面・端末枠・ステータスバー・キーボードを含むデバイス一式へ一様に適用する。入れ子の画面コンテンツだけを拡大・縮小するものではない。
- `placement` は既存のデバイス余白内で縮小後の外形を左端・中央・右端へアンカーする。単なる `transform: scale()` でレイアウト上の占有領域だけを残さない。
- 縦位置は今回追加しない。`background` / `card` 層のデバイスと `standing` 層の立ち絵の衝突を自動検出・自動回避もしない。利用者は右側の立ち絵に対してデバイスを `left` に置く、といった構図を選ぶ。

### 編集UI

- テンプレート定義は `scale` を数値入力（最小0.6、最大1、刻み0.05）、`placement` を選択入力として公開する。
- UI は未指定の `scale` を100%、未指定の `placement` を中央として表示する。100%または中央へ戻したときは、それぞれの保存値を省略する。

## 非ゴール

- VisualCue 全体に共通の自由座標、共通 `scale`、衝突回避エンジンを導入しない。
- `list.callout@1` の幅・揃え・レイアウトを変更しない。
- 立ち絵の倍率・端・高さの契約を変更しない。
- flow のノード形状、アイコン、任意位置レイアウト、辺の自動交差回避を追加しない。
- 表・グラフの個別セル、系列、軸だけを拡大縮小する操作を追加しない。

## 受け入れ条件

1. 横型・縦型とも、flow の短い日本語ノードラベルは不自然な文字途中の折返しなく読める。
2. flow の最小文字サイズでも収まらないラベルは保存できるが、該当ノードのパスを持つ警告が返る。
3. 表と棒グラフは3段階の幅で保存・復元・プレビュー・MP4レンダーでき、`wide` または未指定は現行と同じ最大幅になる。
4. デバイスフレームは0.6〜1の倍率と左・中央・右の配置を保存・復元・プレビュー・MP4レンダーできる。
5. 指定のない既存Cueは、今回追加する任意フィールドによって入力JSONが破壊されない。
6. `list.callout` の入力契約とレンダリングは変わらない。
