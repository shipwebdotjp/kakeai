# テンプレート・レイアウト改善 ロードマップ

[仕様](./spec.md) を正とする。この改善は、各テンプレートが必要とするレイアウト制御だけを追加し、将来のCue共通レイアウト機構を先取りしない。

## Phase 1: テンプレート内の可読性と占有幅

対象は `flow.diagram@1`、`table.simple@1`、`chart.bar@1`。

1. flow のノードラベルを自動縮小し、縮小・収まり切らないケースを警告する。
2. 表と棒グラフに `wide` / `medium` / `narrow` の幅プリセットを加える。
3. 横型・縦型で、文字の可読性と既存の効果・アニメーションが保たれることを検証する。

成果は、データ量に応じた可読性の判断を利用者ができ、表・グラフが立ち絵と共存しやすい構図を選べることである。

## Phase 2: デバイスフレームの構図選択

対象は `scene.device-frame@1`。

1. デバイス一式の `scale` と `placement` を追加する。
2. 縮小後の外形を基準に左・中央・右へアンカーし、デバイスの画面だけが変形しないことを検証する。
3. 立ち絵があるSceneで、左寄せ・右寄せ・中央の意図がプレビューとレンダーで一致することを確認する。

成果は、画面右上のラベルや左右の立ち絵と、デバイスフレームの関係を編集者が明示的に選べることである。

## Phase 3: 利用状況の評価

実装後、実際の作品で次を評価する。

- 表・グラフを縮めても、左右寄せや安全領域が必要なケースが継続しているか。
- デバイス以外にも、立ち絵との共存のための横配置が必要なテンプレートが増えているか。
- テンプレートごとの設定が増え、Cue共通の構図契約へ統合する価値が出ているか。

この段階で複数テンプレートに同じ「縮小＋アンカー＋安全領域」要求が繰り返された場合に限り、VisualCue 共通の配置契約を別機能として検討する。自由座標や衝突回避をこの改善の続きとして自動的に導入しない。
