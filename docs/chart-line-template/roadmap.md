# 折れ線グラフテンプレート ロードマップ

[spec.md](./spec.md) を正とする。`chart.line@1` は L1〜L4 を完了して実装済みである。この文書は実装順と、初期版へ持ち込まない候補を共有する。

## 導入順序

| フェーズ | 対象 | 依存 | 目的 |
| --- | --- | --- | --- |
| L1 | 契約・図形アクション | なし | 入力の境界、意味参照、`draw`、値軸導出を一意にする |
| L2 | レンダラー・効果 | L1 | 直線、マーカー、決定的な描画・シークを実現する |
| L3 | 編集UI | L1 | グリッド編集と効果参照を安全に編集できるようにする |
| L4 | 検証・公開 | L2–L3 | 保存、プレビュー、MP4、外部入力の一致を確認し、出荷文書を同期する |

## 段階導入

### L1: 契約を先に固定する

`chart.line@1` を新しいVisualTemplateとして登録する。既存の `{ columns, rows }` の形を使いながら、カテゴリ値の一意性、最小2カテゴリ、有限数値、全系列の同一書式、軸単位の境界を追加する。個別点を含む効果targetは配列添字ではなく `categoryKey` / `seriesKey` を使う。

`draw` は `FigureAction` の有限語彙へ足す。`emphasize` と `value` は既存のCue効果語彙をテンプレート固有のtargetへ適用するだけであり、図形アクションへ加えない。

成果は、不正な正本JSONを保存できず、既存の `chart.bar@1` を再解釈せずに折れ線だけの契約を取得できることである。

### L2: レンダリングを決定的にする

カテゴリを等間隔に置き、各系列をSVG直線パスと点マーカーで描く。Y軸は仕様のnice ticksで決める。パス長を出力座標から計算し、破線オフセットとマーカー時刻に共用するため、ブラウザのレイアウト計測や `getTotalLength()` に依存しない。

成果は、`draw` の進行とマーカー表示、強調、値カウントが同じシーク位置で再現され、プレビューとMP4が一致することである。

### L3: 意図を壊さず編集する

グリッドでは空セル・重複カテゴリ・書式混在を保存前に明示する。カテゴリ値または系列キーを変更する操作は効果targetも同時に書き換え、削除は影響する効果を確認してから同時に行う。外部からの全置換入力は曖昧な補修をせず、参照エラーとして扱う。

成果は、利用者が個別点を強調する意図を保ったまま、データとセリフ同期効果を編集できることである。

### L4: 出荷判断

契約・導出・レンダラー・フォームの境界をテストし、正値、負値、全値同一、複数系列、長いカテゴリ名、値ラベル、各targetの代表図を視覚確認する。実装完了後だけ、MVP契約・ユーザーガイド・Agent Accessへ対応済みとして記載する。

## 将来候補

| 候補 | 保留理由 |
| --- | --- |
| 日付・数値間隔を反映するX軸 | 現在の文字列カテゴリとは別の入力型・目盛り・欠損規則が必要 |
| 欠損値で線を切る | `null`等の正本表現、値ラベル、効果targetの意味を追加で決める必要がある |
| 曲線補間・ステップ線 | 中間値の意味、パス長、点マーカー時刻、描画の忠実性を別途判断する必要がある |
| 面グラフ・積み上げ | 値軸と系列比較の意味が変わるため、折れ線の単純な派生ではない |
| 手動Y軸・0始まり切替・第二軸 | 視覚的誇張、単位混在、入力複雑化を招くため、実例が出てから判断する |
| 値ラベルの自動間引き | 値を黙って隠す危険がある。重なり警告の利用実績を見てから検討する |
| 追加の図形アクション | `draw` で不足する具体例が確認されるまで、任意CSSや任意easingを持ち込まない |
