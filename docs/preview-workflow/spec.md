# プレビュー操作とドラフト・プレビュー 仕様

この文書は、プレビューの移動操作の信頼性向上と、未保存編集のドラフト・プレビューを正とする。保存は引き続き明示操作のみであり、`ScriptVersion`・レンダー・TTSジョブは保存済み版だけを対象にする。ADRは追加しない。

関連: [../editor/spec.md](../editor/spec.md)（編集画面と再生コントロール）、[../mvp/spec.md](../mvp/spec.md)（正本・派生の境界）、[../mvp/api-contract.md](../mvp/api-contract.md)（プレビュー契約）。

## 共通方針

- ドラフト反映は有効なフォーム状態の全編集を対象とする。
- ドラフト更新中のナビゲーションは、画面に実際に表示されている最後の有効なプレビューを基準にする。
- 自動プレビューは確認用の派生物であり、履歴、版番号、保存状態を変更しない。
- Webはプレビューの解決済みタイムラインだけをシーク基準にし、尺の算出ロジックを二重実装しない。

## Phase 1 — プレビュー操作の信頼性とキーボード操作

### 移動の集約と再生状態

- Player操作は共通の移動関数へ集約する。移動前に再生状態を読み、`seek()` 後は再生中だった場合のみ自動再開し、停止中は停止を維持する。
- HyperFrames Playerの `seek()` は同期的に一時停止するため、再開は移動関数が明示的に行う。

### 意味的ジャンプの1フレーム補正

- Scene・セリフ・Cueの開始点への意味的ジャンプは、開始時刻の1出力フレーム（`1 / timeline.fps`）後へシークし、フレーム境界で前フレームが表示される問題を避ける。総尺を超えないよう丸める。
- ±秒とコマ送り／戻しは指定された時刻・1フレーム量をそのまま使い、補正は加えない。
- Sceneジャンプは遷移の開始（Scene区間の開始）を基準にする。フェード／クロスフェード中に前Sceneや背景が見えるのは正しい演出として維持する。

### 解決済みタイムラインのCue開始時刻

- previewレスポンスの `timeline.scenes[i]` は `{ cueId, startMs }` のCue開始時刻（絶対ms、遷移を含むScene区間基準）を持つ。算出はAPIの共通タイムライン解決器で行う。
- プレビューで表示中のCompositionと同じ解決済みタイムラインを、右ペインの操作、左ペインのScene／Cue／セリフジャンプ、セリフカードのジャンプに共通利用する。

### キーボード操作

- プレビューの表示領域をフォーカス可能にし、フォーカスがその領域にあるときだけ次を有効にする。
  - `Space`: 再生／一時停止
  - `←` / `→`: 選択中の秒数だけ戻る／進む
  - `Shift+←` / `Shift+→`: コマ戻し／送り
  - `J` / `L`: 前／次のセリフ
  - `Shift+J` / `Shift+L`: 前／次のScene
- テキスト入力、セレクト、テキストエリア、ボタンへの通常のキーボード操作は奪わない。フォーカスがそれらにある場合は処理しない。

### セリフカードからのジャンプ

- 各セリフカード見出しに、プレビューだけを該当セリフへ移動する操作を追加する（中央ペインのスクロールは行わない）。左ペインのジャンプは維持する。

### プレビュー操作群の案内

- プレビュー操作群にショートカットの案内を表示し、ユーザーガイドの編集・プレビュー節を更新する。

## Phase 2 — 未保存内容のドラフト・プレビュー

### API

- `POST /language-editions/:editionId/draft-preview` を追加する。本文は `{ content: ContentDocument }` とし、DBへの書込み、ScriptVersion作成、Job作成、ファイル保存、キャッシュ保存を一切行わない。
- `packages/contracts` に `DraftPreviewRequest` と `DraftPreview` のZod契約を追加する。ドラフト応答は `source: { kind: "draft" }`、Composition HTML、素材URL、レンダラー情報、解決済みタイムラインを返す。既存の保存済みプレビューDTOは維持する。
- APIでは言語版の存在、ContentDocument、参照素材の準備完了状態を検証し、保存済みプレビューと同じコンパイラ・asset resolverで合成する。失敗は既存の検証・`PREVIEW_INPUT_INVALID`・素材エラーとして返す。

### Web

- フォームから構築・検証できる未保存Documentだけを、500msのデバウンス後に送信する。古い要求は中止し、遅れて届いた応答は採用しない。
- 入力が一時的に不正、またはドラフト合成に失敗した場合は、最後に成功したCompositionを表示し続け、未保存変更が未反映である状態を示す。
- ドラフト応答を受けたらPlayerを更新し、更新前の絶対時刻を新しい総尺に丸めて復元する。更新前に再生中なら、Playerの準備完了後に同じ時刻から再開する。
- 保存成功後は保存済み版プレビューへ戻す。レンダーとTTSには常に保存済み版IDを渡し、ドラフトを対象にしない。
- 通常時の「更新」ボタンは廃止し、失敗時だけ同じ保存済み版または同じドラフトを再試行できる操作を出す。
- 「プレビューは未保存の有効な編集を反映するが、保存・レンダー対象は最後に保存した版」という区別をユーザーガイドに明記する。

### バックグラウンドCueの確認フロー

- 背景Cueをセリフ区間へ追加して保存せずに確認し、続けて別Cueを追加できること、保存後のレンダーが保存済み版だけを使うことを確認する。

## 非ゴール

- 台本の自動保存、版の自動作成。
- TTS・レンダー対象へのドラフト利用。
- プレビュー履歴の永続化。
