# トラブルシューティング

ライブ配信で問題が起きたときの確認順です。まずライブアプリのターミナル出力と、コンソールの「通知」「イベント」を確認してください。

## 起動できない

### `--package は必須です` / `--run-config は必須です`

```sh
npm run live -- --package /tmp/live-package-v2 --run-config /tmp/live-run/run-config.json --config /path/to/live-config.json
```

`--package` にライブパッケージのディレクトリ、`--run-config` に Live Run が書いた Run 設定 JSON を指定してください。通常は Kakeai の Run 画面から起動します。`--help` で使い方を確認できます。

```sh
npm run live -- --help
```

### パッケージの検証に失敗する

起動時に、パッケージの次の点を検証します。

- `manifest.json` と `show.json` のスキーマ
- ファイルの欠落、manifest にない余計なファイル
- SHA-256 とファイルサイズの不一致
- パッケージ外へ出るパス、絶対パス、シンボリックリンク
- 未対応の mediaType、素材カードの音声混入
- CutInのMP4・尺・音声・寸法・参照の不整合
- 必須フォントの不足

エラーメッセージに表示されたファイルを確認してください。パッケージは書き出し後に変更しない前提です。変更した場合は、もう一度 `live:export` で書き出し直してください。

任意フォントの不足は警告で起動できます。必須フォントの不足は停止します。

### ポートが使用中

```text
EADDRINUSE
```

別のアプリがポートを使っています。`--port` で変更してください。

```sh
npm run live -- --package /tmp/live-package-v2 --run-config /tmp/live-run/run-config.json --port 3011
```

OBS の URL とコンソールの URL も新しいポートに合わせてください。

### Host / Origin で拒否される

ライブアプリは `127.0.0.1` だけで待ち受け、Host と Origin を検証します。`http://127.0.0.1:<port>` または `http://localhost:<port>` で開いてください。別ホスト名や別 origin からは接続できません。

## 書き出し

### CutInを含むパッケージを書き出せない

- `ASSET_NOT_FOUND`（422）: `cutIns[].assetId` のAssetが見つからない
- `ASSET_PROCESSING`（409）: Assetが取り込み中。完了後に書き出し直す
- `ASSET_UNAVAILABLE`（422）: Assetの取り込みに失敗している。動画をアップロードし直す
- `VALIDATION_ERROR`（422）: `assetId` が動画以外のAssetを指している、または `cutInId` などの参照が不正
- `LIVE_EXPORT_CUT_IN_FAILED`: 動画のprobeや正規化に失敗した、尺や動画ストリームを取得できない

`cut_in` セグメントから参照していない `cutIns[]` も、`assetId` が ready な動画Assetであることは検証されます。使わないCutInは削除するか、有効な動画Assetを指定してください。

## YouTube の認証・コメント

### `YouTube の認証情報がありません`

OAuth のみの設定で、トークンがまだ保存されていない場合に出ます。`live auth` を実行してください。

```sh
npm run live -- auth --config /path/to/live-config.json
```

`youtube.apiKey` を設定している場合は、このエラーは出ません。API キーだけで起動でき、`live auth` は不要です。

### `invalid_grant` / 認証が失効している

OAuth 同意画面が Testing の External アプリの場合、リフレッシュトークンは通常 7 日で失効します。コンソールの認証期限を確認し、`live auth` で再認証してください。

トークンは `<dataDir>/auth/youtube.json` に保存されます。ファイルを削除した場合も再認証が必要です。API キーのみの運用では、この失効は関係ありません。

### API キーが拒否される（400 `keyInvalid` / 403）

- Google Cloud で **YouTube Data API v3** が有効になっているか確認する
- API キーの「API の制限」に **YouTube Data API v3** が含まれているか確認する
- API キーの値をコピーし直す。余分な空白や改行が入っていないか確認する
- キーを削除・再作成した場合は、設定ファイルの `youtube.apiKey` も更新する

API キーが認証系のエラーで失敗し、`youtube.clientId` / `clientSecret` と有効な OAuth トークンがある場合、ライブアプリは自動で OAuth に切り替えて同じリクエストを 1 回だけ再試行します。コンソールの認証方式が `OAuth` になり、`OAuthフォールバックあり` と表示されます。

`403 liveChatDisabled`、`403 liveChatEnded`、`404 liveChatNotFound` は認証では解決しないため、フォールバックしません。配信状態と `liveChatId` を確認してください。

### OAuth フォールバックに切り替わらない

- 設定に `youtube.clientId` と `youtube.clientSecret` の両方があるか
- `live auth` でトークンを保存したか。`<dataDir>/auth/youtube.json` があるか
- トークンが 7 日失効していないか。コンソールの認証方式と認証期限を確認する
- エラーが `liveChatDisabled` など認証以外の理由でないか

API キーだけで動いている間は OAuth トークンは使われません。フォールバックが必要なときだけ遅延して読み込まれます。

### `liveChatId` を解決できない

- Run の `videoUrl` が実際のライブの URL か確認する（ローカル設定の `youtube` からは補われません）
- 配信が開始され、ライブチャットが有効になっているか確認する
- API キーを使う場合、YouTube Data API v3 が有効で、キーの制限に含まれているか確認する
- 自動解決できない場合は、Run の `liveChatId` を直接設定する
- コンソールの「liveChatId」欄から手動設定することもできる

### コメントが表示されない

- コンソールの「コメントソース」が `polling` になっているか
- 認証方式（APIキー / OAuth）とフォールバックの有無、最終エラー、クォータ、認証期限を確認する
- コメントはコメントコーナーの開始時にまとめて選ばれる。台本パート中はまだ表示されないことがある
- `freshnessMin` より古いコメントは AI 候補から外れる。ピンは残る
- コメント一時停止になっていないか
- URL・個人情報・攻撃的な表現はブロックされる
- fixture の Run で fixture が空になっていないか。Run 作成時に指定した fixture の内容を確認する

### クォータが心配

コンソールにリクエスト数と units の概算が表示されます。コメント取得は `liveChatMessages.list` のポーリングを使い、`streamList` は使いません。ポーリング間隔は API の `pollingIntervalMillis` に従います。API キーから OAuth への再試行も 1 リクエストとして数えます。30 分の配信で既定のクォータに収まるか、コンソールの概算を確認してください。

## LLM

### 実 YouTube で外部 LLM が拒否される

実 YouTube の実行では、`llm.mode` が `local` で、`baseUrl` がループバックである必要があります。外部 LLM は fixture の Run だけで使えます。設定を確認してください。

### ローカル LLM に接続できない

- `ollama serve` など、ローカル LLM が起動しているか
- `llm.baseUrl` が `http://127.0.0.1:<port>/v1` になっているか
- `llm.model` が導入済みのモデル名か
- ターミナルにタイムアウトや接続エラーが出ていないか

LLM が失敗しても、準備済みの台本は止まりません。そのコメントの生成レスはスキップされるか、退避キューが使われます。

### 生成レスが毎回スキップされる

- `llm.timeoutMs` と TTS の応答速度を確認する
- Live Program のプレイアウト設定 `maxThinkingMs` が短すぎないか確認する。短いと、生成が間に合う前に退避キューへ切り替わります
- 退避キューが使われた場合は、コンソールの通知と `events.jsonl` に理由が残る

## TTS

### `TTS アダプター ... の接続設定がありません`

パッケージ内の話者が使うアダプター ID に対して、`tts.adapters` の `baseUrl` を設定してください。

```json
{
  "tts": {
    "adapters": {
      "voicevox": { "baseUrl": "http://127.0.0.1:50021" }
    }
  }
}
```

### TTS に接続できない・失敗する

- VOICEVOX / AivisSpeech / OpenAI 互換 TTS が起動しているか
- `baseUrl` が正しいか
- パッケージの声 ID・モデル・参照音声が TTS エンジンで利用できるか
- 参照音声を使う場合、パッケージに参照音声が含まれ、同じ Mac の TTS エンジンから読めるか
- `tts.timeoutMs` が短すぎないか

TTS が失敗した生成キューは `failed` になり、次の候補または退避キューへ進みます。準備済みキューの音声は止まりません。

## OBS・音声

### ステージが `PREVIEW` になる

program ステージは 1 つだけです。OBS のステージより先に別のブラウザで `/stage` を開いていないか確認してください。コンソールの「ステージ接続」で OBS のステージを選び、「program を引き継ぐ」を押します。

`?preview=1` は常に preview です。OBS には `/stage` を指定してください。

### 音声が出ない・二重に聞こえる

- OBS のブラウザソースで「音声を OBS で制御する」がオンか
- macOS のデスクトップ音声とブラウザソース音声の両方を配信していないか
- コンソールのステージが `PROGRAM` か
- 別のブラウザで同じステージを開いていないか
- OBS の音声モニタリングと配信トラックを確認する

### CutInが再生されない・すぐ次へ進む

- CutInの動画がパッケージに含まれているか、`manifest.json` の `kind: "cut-in"` と `show.json` の `cutIns[]` を確認する
- 書き出し時に動画の尺・音声・コーデックの検証で失敗していないか確認する
- 再生に失敗した場合、コンソールと `events.jsonl` に警告が残り、番組は次のセグメントへ進みます。配信を止めたい場合は「一時停止」を使ってください
- 終了イベントが届かない場合も、尺＋1500ms（最低3000ms）のwatchdogで打ち切られ、次のセグメントへ進みます
- program ステージがCutInを再生しているか確認する。preview は映像だけをミュートで表示します

### CutInの音声が出ない

- program ステージか確認する。コンソールのプレビューは常にミュートされるため、プレビューで音が出ないのは正常です
- 動画に音声トラックがあるか、書き出し時の `hasAudio` を確認する
- OBS の音声経路が「音声を OBS で制御する」になっているか確認する

### ステージが止まった・再接続した

ライブアプリはサーバやステージの自動復帰を行いません。OBS のブラウザソースを再読み込みした場合は、コンソールで program を引き継ぎ、「再開」を押してください。サーバ自体が落ちた場合は、ライブアプリを再起動し、新しい実行としてやり直します。

## 配信の操作

### 安全モードから戻れない

安全モードはラッチ（解除不可）です。生成レスを止め、準備済みの安全なキューだけを流します。通常の進行に戻すには、配信を終了してライブアプリを再起動してください。

### 終了を押したのにすぐ終わらない

「終了」は現在のキューまたはCutInの再生が終わってからクロージングへ進みます。CutInの開始前に終了が保留されている場合は、そのCutInを飛ばします。すぐに止めたい場合は「停止」を使ってください。

### ピンしたコメントが拾われない

- 安全ブロックされたコメントは、人間がピンしても拾われません
- ピンは次のコメントコーナーで使われます。現在の台本の途中には割り込みません
- ピンがコーナーの枠を超えた場合、`maxExtraSlots` まで延長し、それ以上は次のコーナーへ回ります

## データとログ

### 保存される情報

- 実行ディレクトリ `<dataDir>/runs/<runId>/` にログと生成音声を保存します
- `comments.jsonl` には生のコメント本文・投稿者名を保存せず、投稿 ID、伏せ字、判定理由、スコアを保存します
- YouTube の API キーはライブ設定ファイルに、OAuth トークンは `<dataDir>/auth/youtube.json` に 0600 で保存します
- 実行ディレクトリを削除すると、その実行のログと生成音声を削除できます
- OAuth を取り消す場合は、Google アカウントの許可を取り消し、`youtube.json` を削除してください。API キーを失効させる場合は、Google Cloud の認証情報からキーを削除してください

`live purge` コマンドはありません。不要な実行ディレクトリは利用者が削除してください。

### ログにエラーが残っている

`errors.log` と `events.jsonl` を確認してください。音声のウォッチドッグ、TTS 失敗、LLM 失敗、退避キューの使用などが記録されます。配信後のレビューとプロンプト改善に使えます。

## 既知の制約

- YouTube の配信作成・開始・終了、チャット投稿、モデレーションは行いません
- YouTube の読み取りは API キーまたは OAuth の `youtube.readonly` だけで、書き込みは行いません
- 実 YouTube はローカル LLM のみです
- コメント取得は `liveChatMessages.list` のポーリングです。`streamList` は使いません
- 台本の途中への即時コメント割り込みは行いません
- 複数利用者、クラウド配信、リモートステージ、縦型配信には対応していません
- サーバクラッシュからの自動復帰はありません
